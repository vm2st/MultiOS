# USB 1.1 и USB 2.0 — MultiOS 0.26-dev-usb12

Неопубликованная development-сборка MultiOS / MultiPulti. Не Release 1.0.

## Область поддержки

Добавлены нативные PCI OHCI и EHCI в BIOS-ядро MultiPulti. UHCI сохранён и включён в общий USB host-слой. Само наличие USB-разъёма не определяет совместимость: важны тип контроллера, скорость устройства, топология и класс периферии.

| Контроллер | Скорость | Реализованные устройства |
| --- | --- | --- |
| UHCI, PCI 0c/03/00 | USB 1.x low/full-speed | HID Boot Keyboard напрямую в root-порту |
| OHCI, PCI 0c/03/10 | USB 1.1 low/full-speed | HID Boot Keyboard напрямую в root-порту |
| EHCI, PCI 0c/03/20 | USB 2.0 high-speed | HID Boot Keyboard напрямую в root-порту |
| EHCI с companion UHCI/OHCI | low/full-speed через companion | Передача порта companion-контроллеру; ввод через его драйвер |
| xHCI, PCI 0c/03/30 | USB 1/2/3 на xHCI | Нативного драйвера нет |

USB 1.1-клавиатура в USB 2.0-порту обслуживается companion-контроллером. EHCI без доступного companion не получает поддержку low/full-speed устройств только благодаря наличию этого драйвера. USB 2.0-устройство, подключённое к xHCI, также не обслуживается EHCI-драйвером.

**Это поддержка USB host + Boot Keyboard, а не всех классов USB.** Нет USB storage/BOT/UAS, внешних USB-хабов и split transactions, мышей, touch, звука, камер, Bluetooth, произвольного HID/NKRO и USB 3.x. USB-накопитель можно использовать для загрузки, если это поддерживает прошивка, но новый нативный USB storage-драйвер в этом патче не появился. Собственное BIOS-ядро по-прежнему работает с системным диском через поддержанный ATA/IDE-путь.

## Что изменилось

1. `drivers/pc-bios/usb.c` — общий выбор хостов и перечисление Boot HID.
2. `platform/pc-bios/usb-host.h` — внутренний интерфейс хоста и общие структуры клавиатуры.
3. `drivers/pc-bios/ohci.c` — firmware ownership, reset, питание и reset root-портов, HCCA, ED/TD, control и interrupt IN, обработка ошибок и переподключения.
4. `drivers/pc-bios/ehci.c` — legacy ownership, reset, asynchronous QH/qTD control, periodic interrupt IN, high-speed enumeration и companion routing; hotplug запускается по изменению root-порта, а не только по FRINDEX.
5. `drivers/pc-bios/uhci.c` — интеграция в общий host-слой; выбор по PCI-классу вместо запрета всех не-Intel устройств. Intel legacy-регистр изменяется только у Intel.
6. EHCI запускается до companion-контроллеров, чтобы low/full-speed устройства перечислялись после передачи портов.
7. Общая проверка USB-дескрипторов: длины, границы, endpoint, interface, скорость и размер control endpoint. `SET_PROTOCOL(boot)` обязателен, `SET_IDLE` допускает отказ.
8. Диагностика `usb` и `devices` показывает UHCI/OHCI/EHCI, MMIO или I/O base, порты, клавиатуры, отчёты, ошибки, отключения и состояние.
9. Сохранены общий HID-декодер, редактор строки, OSK, двухкнопочное управление, PS/2 и COM1 fallback в режиме auto.
10. Расширенная BIOS RW-сборка включает все три драйвера. Компактная сборка также собирается; для неё уменьшен резерв контроллеров и добавлен недостающий i386 helper деления.

## Использование

В режиме `auto` драйверы выбираются автоматически. Команды:

```text
ver
usb
devices
osk on
osk off
```

В отчёте ищите `keyboards=1` и `status=boot-keyboard active`. `reports` увеличивается при USB-вводе. Отсутствие такого состояния не доказывает отказ прошивки UEFI: её ввод учитывается отдельно.

Настройки `bios_input` сохраняют значения `auto`, `usb-only`, `ps2-only`. Изменение настроек образа — только на выключенной копии через `tools/customize.py`; редактор создаёт новый файл. `ps2-only` не запускает нативный USB-стек. `usb-only` не читает PS/2 и COM1, поэтому без поддержанной USB-клавиатуры командный ввод отсутствует.

Для диагностики можно включить `osk=on`; события клавиатуры F6/F7 управляют экранной клавиатурой, F5 остаётся необязательным действием «предыдущий». Новый драйвер USB-мыши или сенсорного экрана этим не добавляется.

После подключения дождитесь перечисления устройства. Нажатия до завершения enumeration не буферизуются как введённый текст. Автоповтор и LED Caps/Num/Scroll этим патчем не добавлены.

## Платформы и ограничения

Новые нативные драйверы сейчас интегрированы в **i386 BIOS-ядро**. Оно работает и на x86-64 ПК в поддержанном BIOS/CSM-режиме. Нативная post-UEFI x64-интеграция не сделана: x64 UEFI-вариант продолжает получать ввод через прошивку с сохранёнными Boot Services. В комплектном образе x64 EFI-путь сохранён из 0.25, не выдаётся за новый нативный EHCI/OHCI-драйвер.

Используются identity-mapped 32-bit DMA, coherent x86 RAM, polling и ограниченные таймауты. IRQ, IOMMU, power management/suspend и PCIe BAR выше 4 ГиБ не реализованы. Требуется поддержанный 32-bit MMIO BAR. Нет гарантии работы с любым vendor/device только по совпадению PCI-класса.

Одна Boot Keyboard на контроллер. В расширенном профиле резервируется до четырёх контроллеров каждого типа, суммарно до 12. В компактном профиле по умолчанию один контроллер каждого типа, чтобы не пересечь резерв стека. Это статические C-модули, не загружаемые `.drv`: изменение драйвера требует сборки и установки соответствующего BIOS-bundle.

OHCI поддерживает interrupt interval до 32 мс, с округлением к более редкому допустимому слоту. EHCI Boot HID ограничен `bInterval` 1..14; очень быстрые интервалы опрашиваются не чаще одного раза в кадр. Поддерживаются 8-байтовые boot reports; конфигурации больше 512 байт у OHCI/EHCI и 500 байт у UHCI не принимаются.

## Сборка

Основной полнофункциональный BIOS RW-профиль:

```sh
make bios-rw
python3 tools/build_bios_rw_image.py ORIGINAL.img NEW.img
```

Installer принимает только подготовленный образ известной схемы с чистым private undo-журналом, не физический диск. Используйте свежую копию исходного образа, не файл с ценными данными. Замена одного `MULTIOS/KERNEL32.BIN` не обновляет raw-копию BIOS-ядра; устанавливайте полный bundle через installer.

Компактный диагностический профиль, не замена расширенного NTFS RW-профиля:

```sh
make image PC_PROFILE=profiles/pc-bios-usb-only.mk
```

Результат — `build/multios.img`; он не содержит расширенного NTFS-3G RW-профиля. Не смешивайте свойства этих двух сборок.

## Проверки

```sh
make test-usb-enum test-hid test-ps2 test-editor
make build/two-buttons-test
./build/two-buttons-test
python3 tests/usb_hosts_qemu.py USB_ONLY_IMAGE.img qemu-system-i386
```

Для интеграционных тестов нужен QEMU с `piix3-usb-uhci`, `pci-ohci`, `usb-ehci`, `ich9-usb-ehci1`, `ich9-usb-uhci1` и соответствующими USB HID-устройствами. Не все дистрибутивные сборки QEMU содержат эти модели. Путь к образу должен вести на подготовленную копию с `bios_input=usb-only`, а `build/bios-rw/kernel.elf` должен соответствовать образу: тест читает диагностический инвентарь ядра для ожидания готовности после переподключения.

Тесты передают ввод QMP→USB HID, не в serial и не PS/2. Они проверяют команды, Shift, Left/Delete, запись/чтение на расходном FAT32-образе, SYNC, отключение/подключение клавиатуры и EXIT. Итоговые принятые сценарии перечислены в отчёте поставки. Unit-тест общего enumeration выполняется с ASan/UBSan; отдельные проверки HID и редактора не являются тестами реального USB-контроллера.

**Реальные контроллеры, кабели, питание и накопители не испытывались.** Эмуляционные результаты не означают промышленную стабильность, полную USB-совместимость или сертификацию USB-IF. Сборка остаётся неопубликованной разработкой, не стабильным выпуском.
