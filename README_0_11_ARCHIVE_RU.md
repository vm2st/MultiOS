## 1. Что уже работает

- Собственный 512-байтный BIOS-загрузчик, чтение ядра через EDD, низкоадресная загрузка, GDT, переход в protected mode.
- Ядро на C/ассемблере без libc, Linux, DOS и стороннего ядра.
- Текстовая консоль VGA 80×25, прокрутка, US PS/2-клавиатура, serial COM1 115200 8N1.
- ATA PIO LBA28: primary master, чтение/запись 512-байтных секторов и flush cache.
- MBR-раздел типа 0x07 с exFAT; в host-режиме также exFAT superfloppy.
- Проверка основной boot checksum, checksums наборов directory entries, checksum UpCase; ASCII NameHash.
- Allocation Bitmap, FAT-цепочки, фрагментированные файлы, contiguous NoFatChain, чтение ValidDataLength с нулевым заполнением неинициализированной части.
- Каталоги, вложенные пути, чтение, создание, замена и дописывание текста, копирование двоичных файлов, переименование, удаление файлов и пустых каталогов.
- Hex-просмотр, CRC32, побайтовое сравнение, поиск текста, сведения о файле и свободном месте.
- По умолчанию read-only; запись включается явно. Dirty volume не разблокируется.
- Host-сборка того же драйвера и shell для быстрой отладки и автоматических тестов.

## 2. x86 и x64 — что означает поддержка

| Конфигурация | Статус |
|---|---|
| 32-битный x86, инструкции i386, BIOS EDD, IDE/ATA | Целевая архитектура; проверка загрузки — модель CPU 486 в QEMU |
| x86-64 с legacy BIOS/CSM и IDE-совместимым диском | То же 32-битное ядро; проверка — модель qemu64 |
| Нативное 64-битное ядро / long mode | Ещё не реализовано |
| UEFI x64 | Отдельный USB live-вариант, см. USB_RU.md; использует драйверы прошивки |
| Secure Boot | EFI-файл не подписан доверенным ключом |
| 8086/8088/80286 | Не поддерживаются: ядру нужен protected mode i386+ |
| AHCI, NVMe, USB storage, virtio-blk | Нет драйверов |
| Любой реальный PC / любая модель x86 | Не обещается; физических аппаратных тестов не было |

Важно: ISA процессора и поддержка платы/диска/клавиатуры/прошивки — разные задачи. Формулировка «на всех x86/x64» недостижима одним драйвером и одним режимом загрузки. Здесь есть исходная архитектурная база, а не универсальный установщик.

## 3. Самый быстрый запуск готового образа

Архив уже содержит `build/multios.img` — raw-образ диска на 64 MiB с MBR, ядром, exFAT и `WELCOME.TXT`. Не форматируйте его повторно.

Установите QEMU и распакуйте архив. Быстрый запуск: `./run.sh` (Linux) или `powershell -ExecutionPolicy Bypass -File .\run.ps1` (Windows). Скрипты автоматически создадут `build/work.img` и сохранят его между запусками. Для ручного запуска из каталога проекта:

```bash
cp build/multios.img build/work.img
qemu-system-x86_64 -machine pc -cpu qemu64 -m 32M \
  -drive file=build/work.img,format=raw,if=ide,index=0 \
  -serial stdio \
  -device isa-debug-exit,iobase=0xf4,iosize=0x04
```

Будут доступны окно VGA и serial в терминале. Раскладка VGA-клавиатуры — английская US; русская раскладка не реализована. Backspace и Ctrl+C поддержаны при вводе строки; когда OSK скрыта, работают Left/Right, Home/End, Delete и история F8/F9; см. CONSOLE_RU.md.

Для полностью терминального режима добавьте:

```bash
-display none -monitor none
```

Если нужна неизменяемость исходного образа независимо от драйвера, используйте копию или QEMU `-snapshot`: изменения уйдут во временный overlay и исчезнут при закрытии.

### Windows

1. Установите QEMU для Windows.
2. Откройте PowerShell в каталоге проекта.
3. Сделайте рабочую копию и запустите:

```powershell
Copy-Item build\multios.img build\work.img
& "C:\Program Files\qemu\qemu-system-x86_64.exe" -machine pc -m 32M -drive "file=build/work.img,format=raw,if=ide,index=0" -serial stdio -device isa-debug-exit,iobase=0xf4,iosize=0x04
```

Путь к QEMU зависит от установки. Сборку исходников удобнее делать в WSL2/Linux; готовый образ можно запускать QEMU под Windows напрямую.

### Что означает EXIT

`EXIT` делает flush и останавливает ядро. При наличии `isa-debug-exit` QEMU завершится с кодом **33** — это ожидаемый результат протокола этого тестового устройства, не ошибка MultiOS. Без устройства CPU остановится; окно эмулятора нужно закрыть вручную. На физическом PC команда не выключает питание.

## 4. Сборка из исходников

Пример для Ubuntu/Debian/WSL:

```bash
sudo apt update
sudo apt install build-essential gcc-multilib binutils python3 qemu-system-x86 exfatprogs
make
```

`gcc -m32` нужен только для freestanding-ядра. Оно не линкуется с 32-битной libc. Host-сборка использует обычную libc вашей Linux-системы.

```bash
make run       # qemu-system-i386, стандартная модель PC
make run64     # qemu-system-x86_64, ядро всё ещё 32-битное
make test      # автоматические тесты, включая загрузку QEMU если он установлен
python3 tests/edge_cases.py
```

`make run` и `make run64` используют непосредственно `build/multios.img`: разрешённые вами записи сохранятся в нём! Для экспериментов рекомендуются команды с `build/work.img` из предыдущего раздела. `make clean && make` создаёт исходный образ заново и удаляет предыдущие изменения в генерируемом образе; заранее сохраняйте свои рабочие копии.

Основные файлы сборки:

- `build/boot.bin` — ровно 512 байт.
- `build/kernel.elf` — ядро с символами для отладки.
- `build/kernel.bin` — загружаемое ядро без ELF-заголовка.
- `build/multios.img` — весь raw-диск, не ISO.
- `build/multios-host` — отладочная Linux-консоль с тем же C-кодом файловой системы.

Ограничение текущего загрузчика: ядро не больше 240 секторов = 120 KiB без BSS. Если оно станет больше, сборка остановится; понадобится дальнейшее расширение загрузчика. Ядро располагается с физического адреса 0x10000, стек — с 0x90000.

### Создание нового чистого образа

```bash
python3 tools/mkimage.py build/new.img --boot build/boot.bin --kernel build/kernel.bin
```

Утилита работает только с **новым файлом**, отказывается перезаписывать существующий путь и не является средством установки на диск. `tools/upcase.bin` — стандартная таблица UpCase, извлечённая из тестового тома, созданного `mkfs.exfat`; зависимости от mkfs при генерации образа нет.

## 5. Первый сеанс

Внутри MultiOS вводите по одной строке:

```text
HELP
DIR
TYPE WELCOME.TXT
DF
UNLOCK YES
MD DOCS
WRITE /DOCS/hello.txt "Hello from MultiOS!"
APPEND /DOCS/hello.txt "Second line"
TYPE /DOCS/hello.txt
COPY /DOCS/hello.txt /DOCS/copy.txt
CMP /DOCS/hello.txt /DOCS/copy.txt
REN /DOCS/copy.txt "renamed copy.txt"
DIR /DOCS
CRC32 /DOCS/hello.txt
FIND "Second" /DOCS/hello.txt
HEX /DOCS/hello.txt
CD /DOCS
PWD
CD ..
TREE /
DEL "/DOCS/renamed copy.txt"
DEL /DOCS/hello.txt
RD /DOCS
SYNC
LOCK
EXIT
```

`UNLOCK YES` — намеренное подтверждение экспериментальной записи, **не гарантия сохранности данных**. На грязном томе команда будет отклонена. После I/O/иной ошибки уже начатой операции записи текущий mount блокируется: не пытайтесь продолжать изменять его.

## 6. Все команды

Регистр команд и ASCII-имён не важен; регистр содержимого файлов сохраняется.

| Команда | Назначение и особенности |
|---|---|
| `HELP`, `?` | Справка |
| `VER` | Версия и имя реально подключённой платформы |
| `PLATFORM`, `HAL` | Платформа, архитектура, HAL ABI, геометрия и возможность записи |
| `DRIVERS` | Реальный перечень native/firmware интерфейсов |
| `OSK ON/OFF/TOGGLE` | Экранная клавиатура; F2/Ctrl+O переключают её |
| `POWEROFF`, `SHUTDOWN`, `REBOOT` | Операции питания при поддержке платформой; проверены в UEFI VM |
| `DIR [путь]`, `LS` | Непосредственное содержимое каталога; по умолчанию текущего |
| `CD [путь]` | Смена каталога; без аргумента показывает текущий путь |
| `PWD` | Текущий абсолютный путь |
| `TREE [путь]` | Дерево каталогов; ограничение рекурсии 8 уровней |
| `TYPE файл`, `CAT` | Текстовый просмотр; непечатаемые байты заменяются точками |
| `HEX файл` | Смещение, hex-байты и ASCII-колонка |
| `STAT путь` | Размер, ValidDataLength, первый кластер, атрибуты, NoFatChain |
| `DF` | Размер кластера, число/остаток кластеров, KiB, RO/RW, dirty |
| `CRC32 файл` | CRC-32/ISO-HDLC, совместимый с `zlib.crc32` |
| `CMP файл1 файл2` | Побайтовое сравнение; показывает первый отличающийся байт или разные размеры |
| `FIND "текст" файл` | Регистрозависимый поиск подстроки и номер строки; не рекурсивный поиск файлов |
| `UNLOCK YES` | Разблокировка записи на чистом томе; в host также нужен `--allow-write` |
| `LOCK` | Flush и запрет следующих записей |
| `TOUCH путь` | Создаёт пустой файл; существующий файл — ошибка, а не обновление времени |
| `WRITE файл "текст"` | Создаёт или заменяет файл; добавляет LF |
| `APPEND файл "текст"` | Дописывает текст и LF; создаёт файл, если его не было |
| `COPY источник назначение`, `CP` | Копия обычного файла, в том числе двоичного; без перезаписи, назначения-каталога и рекурсии |
| `REN путь новое_имя` | Переименование в том же каталоге; новое имя без пути. Межкаталожного MOVE нет |
| `DEL файл`, `RM` | Удаление одного файла без корзины; каталог удалить этой командой нельзя |
| `MD путь`, `MKDIR` | Создание одного каталога; родитель должен существовать, аналога `-p` нет |
| `RD путь`, `RMDIR` | Удаление только пустого каталога; текущий каталог и его предки защищены |

| `HISTORY` | Показывает одну предыдущую команду; не полноценный журнал |

| `EXIT` | Flush и остановка |

### Правила ввода

- Абсолютный путь начинается с `/`; также принимается `\` как разделитель.
- Относительные пути, `.` и `..` нормализуются. Выше корня подняться нельзя.
- Внутренний текущий путь — не более 255 ASCII-байт вместе с ведущим `/`.
- Строка ввода — до 511 символов, до 16 аргументов вместе с командой. Переполненная строка **не выполняется**.
- Для пробелов используйте двойные кавычки: `TYPE "my file.txt"`.
- Escape-последовательностей `\n`, экранирования кавычки внутри аргумента, пайпов `|`, перенаправления `>`, wildcard `*`, DOS BAT-файлов и переменных окружения пока нет; собственные ASCII-сценарии запускаются командой SOURCE.
- `WRITE` и `APPEND` принимают один текстовый аргумент. Они не являются многострочным редактором. `COPY` копирует двоичные файлы побайтно.
- Имена создаются только в диапазоне ASCII 0x20–0x7E, без управляющих символов и запрещённых exFAT `" * / : < > ? \ |`; конечные точка и пробел запрещены как дополнительное ограничение интерфейса.
- Имена Unicode видны как `?` с пометкой; обращаться к ним, менять или удалять их по такой замене нельзя. Содержимое TYPE также не отображается как UTF-8. Поддержка русских имён/раскладки — отдельный будущий этап.
- Корень отображается `/`, а не `C:\`. Буквы дисков и выбор нескольких томов пока не реализованы.

## 7. exFAT: поддерживаемое подмножество

- FileSystemRevision 1.00, одна FAT, логический сектор **512 байт**.
- Размер кластера 512 байт–64 KiB. Основной поставляемый образ использует 4 KiB.
- Один том; первый MBR-раздел типа 0x07 либо superfloppy в host-режиме. GPT и TexFAT не поддерживаются.
- ATA LBA28: адресуемый диск не более 128 GiB. Это ограничение драйвера, не exFAT.
- Длины и смещения в прототипе 32-битные; файлы >=4 GiB не поддерживаются, создание данных ограничено 0xFFFF0000 байтами. Большие файлы могут отображаться как неподдерживаемые. Практические тесты проведены на малых образах, не на предельных размерах.
- Метаданные UpCase проверяются; текущая реализация требует обычного не сжатого ASCII-префикса таблицы. Некоторые допустимые альтернативно сжатые таблицы будут отвергнуты.
- Каталоги **не расширяются автоматически**. Корень образа выделен на 8 кластеров = 32 KiB; новый каталог — один кластер. При заполнении — `disk or directory full`, без автоматического расширения. Длинные имена занимают больше записей.
- Новые данные создаются в FAT-цепочках. Чтение сторонних NoFatChain-файлов поддержано.
- Read-only атрибут файла препятствует записи/удалению/переименованию. Команды изменения атрибутов пока нет.
- Временные метки новых/перезаписанных файлов — корректная фиксированная дата 1980-01-01, а не текущее время. RTC и корректное время модификации ещё нужны. Перезапись не сохраняет исходные временные метки; переименование их сохраняет.
- Дополнительные vendor secondary entries и неизвестные critical features поддерживаются не полностью: драйвер может отклонить операцию/каталог. Это не полный драйвер exFAT общего назначения.
- FAT-поиск не кэшируется: многократное прохождение цепочек замедляет работу с большими файлами. Production-оптимизации пока не сделаны.

## 8. Как устроена запись и чего она не гарантирует

1. До изменения структур устанавливается VolumeDirty и выполняется flush.
2. Выделение кластеров учитывает Allocation Bitmap, а не только FAT.
3. Замена/дописывание файла выполняются в новую цепочку; старые кластеры освобождаются после публикации новой записи. Поэтому требуется свободное место под **весь итоговый файл**, а не только добавленный текст.
4. Контрольные суммы набора записей и NameHash пересчитываются.
5. После успешного завершения выполняются flush и снятие Dirty.
6. Ошибка внутри начатой операции оставляет грязное состояние и запрещает дальнейшую запись в текущем сеансе.

**Это не журналирование, не атомарная транзакция, не rollback и не гарантия crash consistency.** Падение питания между записями может оставить утечки кластеров, повреждённый entry set или незавершённое переименование. Secondary-first публикация уменьшает некоторые риски, но не устраняет их. При сбое нельзя «лечить» диск снятием dirty flag вручную.

Не используйте образ одновременно из QEMU, другой VM, host-консоли и смонтированной файловой системы. Host-консоль берёт advisory file lock, но сторонние программы не обязаны его соблюдать.

## 9. Host-консоль: тот же драйвер без загрузки ОС

```bash
cp build/multios.img build/host-work.img
build/multios-host build/host-work.img                # только чтение
build/multios-host build/host-work.img --allow-write  # право разблокировать запись
```

Во втором случае всё равно требуется `UNLOCK YES` внутри shell. Host-режим принимает только обычные файлы-образы, отказывается открывать block devices и конечные симлинки, проверяет секторное выравнивание/длину, берёт эксклюзивный advisory lock. Он предназначен для Linux/POSIX и не является бинарником для Windows.

Host-режим сам по себе **не ОС**; он нужен для тестирования тех же `lib/exfat.c` и `lib/shell.c`, которые встраиваются в загрузочное ядро. Команды VER и PLATFORM явно показывают, что host-программа — POSIX harness, а не загруженная ОС.

## 10. Независимая проверка и восстановление

При выключенной VM извлеките раздел из копии образа:

```bash
python3 - <<'PY'
from pathlib import Path
with open('build/work.img', 'rb') as f:
    f.seek(2048 * 512)
    Path('build/work.exfat').write_bytes(f.read())
PY
fsck.exfat -n build/work.exfat
```

`-n` — только проверка, не исправление. Восстановление сначала пробуйте **на ещё одной копии**: `fsck.exfat` вашей версии поддерживает интерактивный/автоматический repair-режим; проверьте `fsck.exfat --help`. MultiOS не реализует CHKDSK и не восстанавливает испорченные тома.

Если вы исправляли извлечённый раздел, сам исходный `.img` от этого не изменится. Для первого этапа безопаснее создать новый чистый образ и заново провести эксперимент, чем вручную переносить исправленный раздел в диск.

### Проверки проекта

```bash
make test
python3 tests/edge_cases.py
```

Тесты используют временные **копии** образов. При установленном `fsck.exfat` проверяют результат независимо от C-драйвера; при установленном QEMU загружают kernel и проверяют чтение/запись на CPU 486 и qemu64.

Для среды без PC-модели QEMU можно отдельно выполнить только host-тесты:

```bash
MULTIOS_SKIP_QEMU=1 python3 tests/test.py
```

Для явного выбора эмулятора:

```bash
QEMU=/path/to/qemu-system-x86_64 python3 tests/test.py
make run64 QEMU64=/path/to/qemu-system-x86_64
```

Отчёты поставки лежат в `build/test-report.txt`, `build/edge-report.txt`, `TESTING_RU.md`. Они описывают выполненные тесты, а не сертификацию для всех носителей/сбоев питания. Синхронные отказы отдельных sector writes проверяются `python3 tests/faults.py` (требуется gcc). Это не имитация исчезновения питания. Проверки torn writes, контроллерных кэшей, crash consistency, fuzzing и тесты на настоящем оборудовании ещё необходимы.

## 11. Частые проблемы

- **unsupported machine type pc**: ваша сборка QEMU не содержит i440fx/legacy PC. Нужна полноценная сборка `qemu-system-x86` с моделью `pc`. Подмена на q35 не поможет: там обычно AHCI, которого у ядра пока нет.
- **ATA primary-master unavailable**: используйте `if=ide,index=0`, обычную модель PC и не NVMe/virtio/q35.
- **Mount failed**: проверьте геометрию, размер сектора, версию exFAT, контрольные суммы; используйте исходный образ для сравнения. Большое число допустимых вариантов exFAT ещё не поддерживается.
- **Read-only**: по умолчанию это нормально. Для одноразовой копии — `UNLOCK YES`; в host также `--allow-write`. Грязный том не разблокируется.
- **Disk or directory full при свободном DF**: закончились записи каталога. Создайте подкаталог; автоматического расширения нет.
- **Клавиатура не печатает/не та раскладка**: используйте serial или эмулируемую PS/2, английскую раскладку.
- **Образ не грузится как ISO**: это raw HDD image; используйте `-drive ... format=raw`, не `-cdrom`.
- **Нет Python/gcc/make в Windows**: используйте WSL для сборки или готовый образ + QEMU Windows.

## 12. Структура проекта и дальнейшее развитие

```text
platform/pc-bios/boot.S          BIOS EDD, A20, GDT, protected-mode entry
platform/pc-bios/boot.ld         компоновка 512-байтного MBR-кода
platform/pc-bios/start.S       старт C-ядра, очистка BSS
platform/pc-bios/platform.c    VGA, PS/2, serial, ATA PIO
platform/pc-bios/link.ld       адреса ядра
include/multios/hal.h контракт платформы
core/hal.c          общий адаптер аппаратного слоя
lib/multi.h          типы и интерфейс ФС
lib/util.c           маленькие freestanding-утилиты
lib/exfat.c          общий драйвер exFAT
lib/shell.c          общий parser и команды
platform/posix/host.c        POSIX block backend для обычного файла
tools/mkimage.py    создание нового 64 MiB образа
tools/upcase.bin    стандартная таблица UpCase
tests/              файловые и загрузочные тесты
build/               результаты сборки и отчёты
```

Рекомендуемая очередность следующих этапов:

1. HAL и платформенный код уже отделены. Следующее: выбрать вторую плату/BSP; добавить E820, IDT, исключения, таймер и безопасный panic для PC.
2. Динамическое расширение каталогов; Unicode UTF-8 ↔ UTF-16, полный decoder UpCase; метки времени, fsck/fuzz/fault-injection.
3. UEFI live-вариант уже добавлен. Далее — собственные драйверы после ExitBootServices, GPT и самостоятельное x64-ядро.
4. PCI inventory и ограниченный USB UHCI/HID добавлены в 0.8-dev. Далее — AHCI, NVMe, OHCI/EHCI/xHCI и USB storage; ATA LBA48 и 64-битные размеры.
5. Аллокатор страниц/heap, paging, процессы, системные вызовы, загрузчик ELF и пользовательские программы.
6. Редактор строки и SOURCE уже добавлены; далее — текстовый редактор файлов и приложения. Двоичная DOS-совместимость потребует отдельной среды реального/V86 режима или эмуляции, а не только похожих команд.

## 13. Формат и лицензия

Собственный код проекта — MIT, см. `LICENSE`. Единый образ содержит MultiOS/MultiPulti, инструкции и исходники проекта; MS-DOS/Windows и их код в проект не включены. UEFI-бинарник линкуется с GNU-EFI: его исходники и уведомления включены в third_party/gnu-efi и THIRD_PARTY_NOTICES.txt. Эмулятор, OVMF, компилятор и exfatprogs не входят в архив и имеют собственные лицензии.

Публичная спецификация, использованная для формата exFAT:
https://learn.microsoft.com/en-us/windows/win32/fileio/exfat-specification

## Основная поставка 0.11-dev

В этом архиве только один готовый `.img`: `build/MultiOS-MultiPulti.img`.
Раздельные BIOS/regression и file-backed USB-образы выше оставлены как build-
цели; готовых `USB_FILES` и этих дополнительных образов в архиве 0.11-dev нет.
Для нового unified-варианта используйте `ONE_IMAGE_RU.md`, а не копирование
папок из старого руководства. Для собственно ядра — `MULTIPULTI_RU.md`.

## CPU-политика 0.6

`CPU_COMPAT_RU.md`: общий i386 baseline, guarded CPUID, отсутствие обязательных
FPU/MMX/SSE/CMOV и матрица QEMU. Новая команда `CPU`; реальный 386 и все платы
не проверены. DOS-подобный BIOS service bridge пока не реализован: текущий
native ATA нельзя выдавать за универсальную аппаратную совместимость.
