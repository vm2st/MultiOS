# MultiOS 0.31-dev-writeops / MultiPulti

Неопубликованная сборка разработки. Не стабильный Release 1.0. Запись FAT32/exFAT/NTFS остаётся экспериментальной; полная совместимость форматов не заявляется.

## Исправления записи

### Копирование защищённого источника

Расширенные адаптеры FatFs (FAT32/exFAT) и NTFS-3G теперь различают права источника и назначения. Атрибуты ReadOnly и System обычного пользовательского файла запрещают его изменение, но не чтение DATA для копирования. Ранее `copyatomic`/VFS mode 4 ошибочно возвращали READONLY для такого источника.

Источник открывается только для чтения. Его данные и защитные атрибуты сохраняются. Новая копия является самостоятельным обычным файлом: её можно изменять. Защита существующего назначения от перезаписи не снята. NTFS-служебные inode, reparse points и EFS не открываются этим изменением для произвольного копирования/записи.

Это копирование обычного DATA, не клонирование всех атрибутов, ACL, времён или ADS. Для поддерживаемого копирования именованных потоков NTFS используется отдельная команда `copyads`, с прежними ограничениями.

### Сохранение регистра NTFS

Список NTFS-каталога возвращает исходное написание имён с диска, а не принудительно строчные имена. Сравнение путей в MultiOS остаётся без учёта регистра. Проверены переименование файла и непустого каталога с изменением только регистра, сохранение содержимого и отказ при занятом имени назначения. Это не полная реализация Windows per-directory case-sensitive semantics.

### Безопасность

Все изменяющие операции по-прежнему выполняются через private undo. Сохранены отказы записи повреждённых/неподдержанных томов, конечный лимит транзакции, защита ReadOnly/System назначения и запрет удаления непустого каталога. Нельзя принудительно снимать защитные отказы.

## Состав и запуск

- `images/MultiOS-0.31-usb-fat32.img`, `-exfat.img`, `-ntfs.img` — три альтернативных raw-образа. Выберите один.
- `MultiOS-0.31-FULL-SOURCES.zip` — весь код, upstream-компоненты с лицензиями, тесты и инструкции.
- `bios-bundle/`, `uefi-bundle/` — согласованные новые BIOS i386 и UEFI x64 бинарники.
- `tools/` — настройщик и INI-профили; `reports/`, `TEST_FS_0_31_RU.md`, `SHA256SUMS` — отчёты и контрольные суммы.

Сначала сделайте резервную копию флешки. Запишите выбранный `.img` побайтово, например Rufus в DD-режиме. Это уничтожает старую разметку и данные в диапазоне образа. Нельзя использовать носитель с ценными данными.

BIOS/CSM требует EDD и поддержанный контроллер. UEFI x64 запускает `EFI/BOOT/BOOTX64.EFI`; бинарник не подписан для Secure Boot. Подписание и установка доверенных ключей не выполняются этой поставкой.

```text
ver
modules
fs
unlock YES
md DEMO
write DEMO/HELLO.TXT "Hello MultiOS"
append DEMO/HELLO.TXT "next line"
copyatomic DEMO/HELLO.TXT COPY.TXT
cmp DEMO/HELLO.TXT COPY.TXT
resize COPY.TXT 8193
writeat COPY.TXT 509 "PATCH"
sync
lock
```

`copyatomic источник назначение` выполняется одной ограниченной undo-транзакцией. `copy` — проверяемое staged-копирование, позволяющее работать порциями; это не одна атомарная операция целиком. Для системного USB запрещено извлечение во время работы.

### Настройка

```sh
python3 tools/customize.py images/MultiOS-0.31-usb-fat32.img --settings tools/ATA.INI --output MultiOS-ATA.img
```

Выбор встроенного драйвера выполняется настройщиком; замена C-драйвера требует пересборки. Не меняйте KERNEL32.BIN отдельно архиватором: raw-копия, файлы и CRC должны совпадать. Прежнее руководство USB/OSK сохранено в USB_STORAGE_0_28_RU.md; текущие ограничения и версия определяются этим документом.

## Сборка

Распакуйте FULL-SOURCES рядом с `images/` и `tools/`. Требуются GCC/binutils, make, Python3, mtools; GNU-EFI runtime собирается из приложенного upstream-архива.

```sh
cd MultiOS
make bios-rw
make FS_PROFILE=profiles/filesystems-ntfs3g.mk uefi
python3 tools/build_bios_rw_image.py ../images/MultiOS-0.31-usb-fat32.img ../rebuilt-ata.img --efi build/BOOTX64.EFI
python3 tools/customize.py ../rebuilt-ata.img --settings ../tools/USB.INI --output ../rebuilt-usb.img
```

Выходной файл должен быть новым. Installer принимает подготовленный образ с чистым журналом; это не установщик на произвольный физический диск. Обычный `make all` собирает другой компактный профиль. Новые исправления записи относятся к расширенным FatFs/NTFS-3G профилям.

## Ограничения, не снятые в 0.31

- 512-байтовые секторы в файловых адаптерах; ограниченные геометрия HAL, audit workspace и undo-бюджет до 4096 изменённых секторов на одну операцию.
- Нет полного интерфейса NTFS ACL/reparse/EFS/$LogFile и восстановления произвольных грязных/гибернированных томов. Это не полная Windows-совместимость NTFS.
- UEFI сохраняет Boot Services и использует firmware Block I/O. Это не нативное post-ExitBootServices ядро x64.
- BIOS использует ATA или UHCI/OHCI/EHCI USB BOT. Нет собственного xHCI, хабов, split, UAS, multi-LUN и 4Kn. На одном host выбирается одно direct device.
- Нет гарантии запуска на любом x86/x64. 8086/286 не поддерживаются.
- Реальное железо, физические отключения питания и Windows chkdsk не проверены. Эмуляция и модель сбоев не заменяют эти проверки.
