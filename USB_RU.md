# MultiOS 0.6-cpu: запуск с флешки и экранная клавиатура

> Текущий снимок: **0.11-dev, не опубликован**. Первая публичная версия — только
> стабильный **Release 1.0**. См. RELEASE_POLICY_RU.md и TWO_BUTTONS_RU.md.

**vm2 studios — t.me/v2vproj | MultiOS / MultiPulti.**

## Что действительно готово

- Самостоятельный старт `EFI/BOOT/BOOTX64.EFI` на **x86-64 UEFI** без установленной Windows/Linux.
- Два варианта доставки: **копирование папок на существующую FAT32-флешку** или запись готового raw USB-образа.
- Собственная консоль и exFAT на C. В USB-варианте exFAT находится в файле `MULTIOS/DATA.IMG` на внешней FAT32. Это не exFAT-раздел флешки и не просто программа для Windows.
- Экранная текстовая клавиатура: стрелки выбирают клавишу, Enter нажимает её; Shift, пробел, Backspace, Enter, Hide, Ctrl+C.
- `OSK ON`, `OSK OFF`, `OSK TOGGLE`, F2 / Ctrl+O для переключения.
- `POWEROFF` / `SHUTDOWN` и `REBOOT` через UEFI Runtime Services, после flush.
- `DRIVERS` показывает реальные реализованные/прошивочные интерфейсы, а не фиктивную коллекцию драйверов.

**Важная архитектурная граница:** USB-вариант является UEFI live environment / EFI application, оставляющей Boot Services активными. Он использует аппаратные драйверы прошивки. Это автономная загрузка без другой ОС, но пока **не native kernel после ExitBootServices** с собственным USB/NVMe-стеком. Оригинальная BIOS-сборка остаётся отдельным freestanding-ядром и поддерживает IDE, не произвольный USB.

## Вариант A — просто скопировать файлы, не форматируя флешку

Подходит для флешки, **уже отформатированной FAT32**, и компьютера с x64 UEFI:

1. Распакуйте архив.
2. Проверьте содержимое флешки и сделайте резервную копию важных данных. Не используйте внутренний системный EFI-раздел.
3. Если в корне флешки уже есть `EFI/BOOT/BOOTX64.EFI`, остановитесь: это существующий загрузчик. Не перезаписывайте его без осознанного выбора и отдельной резервной копии.
4. Скопируйте **содержимое** `USB_FILES` в корень флешки. Получится:

```text
<корень FAT32-флешки>/
  EFI/BOOT/BOOTX64.EFI
  MULTIOS/DATA.IMG
  MULTIOS/BOOT.CFG
  MULTIOS/OSK.ON
  MULTIOS/README.TXT
```

5. Безопасно извлеките флешку.
6. Подключите её к целевому компьютеру и в boot menu выберите **UEFI: имя флешки**. Нужна поддержка загрузки с неё со стороны прошивки. В legacy/CSM-режиме этот USB-вариант не запускается.

Копирование не требует установки MultiOS на внутренний диск. Образ данных можно переносить вместе с флешкой. В каталоге `MULTIOS` нет зависимости от абсолютного пути вашей Windows/Linux-системы.

**Нельзя обещать любую флешку в любом состоянии:** NTFS/exFAT на самой флешке стандартным UEFI не гарантируются; 32-битный UEFI, ARM и повреждённые/нестандартные устройства этой сборкой не поддерживаются. В качестве носителя нужен исправный USB-накопитель с достаточным свободным местом (порядка 64 MiB для поставляемых файлов).

## Вариант B — записать готовый образ

`build/multios-usb-uefi.img` — raw disk image на **129 MiB**, MBR + FAT32 с UEFI fallback loader и DATA.IMG.

Запишите его инструментом записи образов, например Rufus в режиме DD или balenaEtcher. Это **не** копирование файла `.img` в папку флешки.

**Запись raw-образа перезапишет таблицу разделов и существующие данные выбранной флешки.** Проверьте её модель, ёмкость и резервную копию; не выбирайте системный диск. Скрипты проекта никогда автоматически не открывают физические диски. Никакой реальный накопитель в тестах разработки не форматировался.

После записи видимый FAT32-раздел имеет размер 128 MiB. Остаток большой флешки образ не использует; автоматического расширения и управления разделами пока нет.

## Secure Boot

Поставляемый EFI-файл **не подписан доверенным платформенным ключом**. При действующей политике Secure Boot прошивка может и должна отказаться его запускать. Поддержка Secure Boot требует собственной подписи, цепочки доверия и корректного управления ключами; такая настройка не выполняется этим прототипом. Подписанный универсальный выпуск здесь не обещается.

## Экранная клавиатура

В поставке присутствует `MULTIOS/OSK.ON`, поэтому USB-вариант сразу показывает панель. Если она не нужна при старте, удалите **только этот маркер-файл** до загрузки; DATA.IMG не трогайте.

- Стрелки — перемещение выделения; движение циклическое.
- Когда панель скрыта, **стрелка вверх снова включает её**. Поэтому включить/выключить OSK можно и только пятью кнопками, без F2.
- Физический Enter / кнопка подтверждения — нажать выбранную виртуальную клавишу.
- Виртуальная **Enter** — передать команду в консоль.
- **Shift** — переключить регистр и верхний ряд символов; выбор сохраняется до повторного Shift.
- **Back** — стереть предыдущий символ.
- **Space** — пробел.
- **Hide**, физический Esc, F2 или Ctrl+O — скрыть панель; F2/Ctrl+O также включают её обратно.
- **CtrlC** — отменить ввод текущей строки.
- Tab передаёт символ табуляции, но shell пока не реализует автодополнение.

Обычные буквенные клавиши по-прежнему можно использовать, но при включённой OSK Enter выбирает виртуальную клавишу. При наличии полной клавиатуры удобно сначала нажать F2 и затем работать обычным образом.

Команды:

```text
OSK
OSK ON
OSK OFF
OSK TOGGLE
```

### Устройство без физической клавиатуры

Нужен **хотя бы один реально поддержанный источник управления**: четыре направления и подтверждение. UEFI-вариант принимает события стрелок/Enter, предоставленные прошивкой. Кнопки устройства подойдут, если прошивка или ваш BSP выдаёт их как такие события.

**Произвольный геймпад, touchscreen, кнопки громкости телефона не поддерживаются автоматически.** Без драйвера и отображения кнопок в события никто не сможет управлять даже экранной клавиатурой. Нативные GPIO/buttons/gamepad/touch-драйверы — следующий отдельный этап. В текущей проверке использован эмулируемый USB HID keyboard; сама команда вводилась только стрелками и Enter, без нажатия букв.

## Драйверы и периферия

| Слой | Есть | Не следует путать с |
|---|---|---|
| Общий код | exFAT, shell, OSK, HAL ABI 2 | полноценным VFS/многозадачным ядром |
| BIOS PC | VGA text, PS/2 set-1, COM1, ATA PIO primary master | нативным USB/AHCI/NVMe |
| UEFI USB | SimpleTextInput/Output, SimpleFileSystem/File I/O, ResetSystem | собственными USB host/HID/storage драйверами MultiOS |

При загрузке UEFI может уже иметь драйверы xHCI, USB storage, USB keyboard, SATA или NVMe. MultiOS использует **то, что действительно предоставляет данная прошивка**. Это позволяет расширить охват на раннем этапе без сотен непроверенных заглушек, но не гарантирует работоспособность любого контроллера. Поддержка Wi-Fi, аудио, камер, принтеров, Bluetooth, графических ускорителей и произвольных USB-классов не заявляется.

```text
PLATFORM
DRIVERS
```

Windows `.sys` и Linux `.ko` нельзя просто скачать и добавить: их ABI не совместим с MultiOS.

### Очерёдность собственных драйверов

1. PCI enumeration и устройство/драйвер registry с диагностикой ID.
2. xHCI + базовый USB enumeration/control/bulk/interrupt transport.
3. USB MSC для накопителей и HID keyboard/buttons; затем EHCI/UHCI/OHCI по необходимости.
4. AHCI и NVMe, затем SD/eMMC для конкретных плат.
5. HID gamepad/touch и GPIO-кнопки через HAL key events.
6. Отдельные сетевые/аудио-драйверы после появления нужных kernel services.

Каждому драйверу нужны конкретные поддержанные ID/ревизии, тесты ошибок, таймауты и измерения. Запись опаснее чтения: не включайте RW у заглушки, возвращающей фиктивный успех.

## Запись и сохранение файлов

По умолчанию том exFAT read-only. На одноразовой копии:

```text
UNLOCK YES
MD DOCS
WRITE /DOCS/hello.txt "Hello from a USB live system"
TYPE /DOCS/hello.txt
SYNC
LOCK
POWEROFF
```

Не вытаскивайте флешку во время работы. Сохранение идёт в DATA.IMG, а затем через firmware file flush — во внешнюю FAT32. Запись экспериментальная и не защищена журналом; при обрыве питания могут пострадать и exFAT-образ, и внешняя FAT32. Сохраняйте резервную копию DATA.IMG.

Для корректной проверки образа данных при выключенной MultiOS:

```bash
fsck.exfat -n USB_FILES/MULTIOS/DATA.IMG
```

`build/multios-host USB_FILES/MULTIOS/DATA.IMG` позволяет проверить файлы на Linux, но это отдельный тестовый harness поверх Linux, не способ автономной загрузки.

## Выключение и перезагрузка

- `POWEROFF` / `SHUTDOWN` — flush, затем UEFI ResetSystem(EfiResetShutdown).
- `REBOOT` — flush, затем UEFI ResetSystem(EfiResetCold).
- `EXIT` — завершение shell; в UEFI-варианте также предпринимается выключение.

Если прошивка не поддерживает нужную операцию, полного выключения обещать нельзя. У старого BIOS-порта нет универсального ACPI poweroff: EXIT останавливает CPU, а не обязательно снимает питание.

## Быстрота загрузки

В тесте QEMU + OVMF + xHCI USB prompt появился приблизительно за **несколько секунд**, точные результаты — `build/uefi-test.log`. Это единичное измерение в эмуляторе, **не SLA для реальных компьютеров**. POST, тренировка памяти, Secure Boot, порядок boot entries и инициализация USB могут занять значительно больше времени ещё до запуска MultiOS.

## Проверка в QEMU

Linux, полноценная x86 QEMU и совпадающая пара OVMF CODE/VARS:

```bash
./run-uefi.sh
```

Если firmware лежит в другом месте:

```bash
OVMF_CODE=/path/to/OVMF_CODE.fd OVMF_VARS=/path/to/OVMF_VARS.fd ./run-uefi.sh
```

Скрипт использует `build/usb-work.img`, а не физический USB. Тестовая VM получает эмулируемые xHCI, USB storage и USB keyboard. Это проверка конкретной прошивки/эмулятора, не физических контроллеров.

## Сборка

Нужны GNU-EFI, dosfstools и mtools дополнительно к предыдущему toolchain. Пример для Debian/Ubuntu:

```bash
sudo apt install build-essential gcc-multilib binutils python3 gnu-efi dosfstools mtools qemu-system-x86 ovmf
make
make usb EFILIB=/usr/lib EFILDS=/usr/lib/elf_x86_64_efi.lds EFICRT=/usr/lib/crt0-efi-x86_64.o
```

Пути GNU-EFI зависят от дистрибутива. Значения по умолчанию в Makefile соответствуют Amazon Linux `/usr/lib64/gnuefi`. `make` по-прежнему собирает BIOS/host; `make usb` дополнительно создаёт UEFI и USB_FILES. При пересоздании USB-сборки генерируемые `build/USB_FILES/MULTIOS/DATA.IMG` и raw USB-образ будут заменены чистыми версиями. Рабочие данные храните в отдельных копиях.

## Что пока не обещается

Любые устройства, ARM/RISC-V USB boot, UEFI IA32, native USB kernel после ExitBootServices, touchscreen без драйвера, Secure Boot, мгновенный cold boot на реальном PC, штатная установка на внутренний диск или безошибочное сохранение важных файлов.

## Модульность в 0.4

`MULTIOS/BOOT.CFG` выбирает готовые драйверы до монтирования тома.
`MODULES` показывает выбранные реализации. Руководство: `MODULES_RU.md`.
`osk=on/off` имеет приоритет над OSK.ON; `osk=auto` сохраняет поведение маркера.
Для замены кода драйвера нужна пересборка EFI, для выбора встроенного — только
редактирование конфига и перезагрузка.
