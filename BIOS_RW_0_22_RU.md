# MultiOS 0.22-dev-biosrw — MultiPulti

vm2 studios | t.me/v2vproj — автор модульного шаблона портирования.
Неопубликованная разработка. Это НЕ стабильный Release 1.0.

## Что изменено

Теперь NTFS-3G работает также внутри собственного 32-битного BIOS-ядра: без Linux, POSIX-процесса, FUSE и UEFI. FAT32/exFAT используют FatFs. В x64 UEFI сохранён прежний NTFS-3G backend. Все три готовых образа содержат обе загрузки и общий раздел данных соответствующей ФС.

BIOS получил расширенный загрузчик, проверку карты E820, включение и проверку A20, проверку размера и CRC32 ядра. Ядро загружается в 1 МиБ; область ядра ограничена 4 МиБ. Собственный аллокатор использует 24 МиБ в диапазоне 4–28 МиБ; стек располагается ниже 30 МиБ. Проверяется доступность диапазона 1–30 МиБ. Нужны минимум 32 МиБ установленной RAM. Это не прежний малопамятный BIOS-профиль.

Новый freestanding runtime использует 64-битные смещения файлов и time_t, но BIOS-источник реального времени ещё не добавлен: время по умолчанию — 2000-01-01 UTC. Это известное ограничение метаданных, а не текущая дата.

## Поддержка и ограничения

- BIOS: целевая ISA i386, проверены QEMU 486, Pentium, Pentium III, qemu64. На x64 с BIOS выполняется 32-битное ядро. Реальный 386 не проверен. 8086/286 не поддерживаются.
- BIOS-загрузка: EDD, диск 80h, накопитель на первичном IDE/ATA master. Загрузчик использует EDD в начале, затем собственный ATA PIO. USB-флешка, представленная BIOS как диск 80h, НЕ становится автоматически доступной ATA-драйверу.
- BIOS AHCI, NVMe, USB Mass Storage, GPT и 4Kn этим патчем НЕ добавлены. Для обычных современных USB-загрузок предпочтителен x64 UEFI с firmware Block I/O.
- UEFI: x64, сохраняет Boot Services; это не нативное x64-ядро после ExitBootServices. IA32 UEFI отсутствует. Secure Boot без самостоятельной настройки доверия не поддерживается.
- NTFS: обычные файлы, каталоги, чтение/запись/append, случайная запись и resize, именованные потоки ADS, hardlink и COPYADS доступны через общий VFS. Подробный синтаксис — HELP и FILESYSTEMS_0_21_RU.md; его указание «UEFI-only» для NTFS RW заменено этим документом.
- Нет полной Windows-семантики ACL/SID, воспроизведения $LogFile, chkdsk, EFS/BitLocker, полного reparse/EA и всех разновидностей NTFS. Нельзя называть это полной совместимостью с Windows NTFS.
- Частный undo-журнал ограничен 4096 изменёнными секторами на операцию; превышение бюджета должно завершаться отказом, а не обещанием неограниченной операции. Это не аппаратная гарантия атомарности и не NTFS $LogFile.
- Небезопасный dirty/hibernated NTFS не разрешается открывать RW. Не обходите эту защиту. Работайте с копиями и резервными копиями.
- Модули — статические C-компоненты. Изменение C-драйвера требует пересборки; простая замена произвольного .drv не реализована. Интерфейсы VFS/HAL сохранены.

## Запуск и запись

Архив содержит образы с разделом данных NTFS, FAT32 или exFAT. Сначала тестируйте копию образа в виртуальной машине. Для BIOS нужен IDE primary master и не менее 32 МиБ RAM. Для UEFI нужен x64 OVMF/совместимый firmware. Используйте режим raw-диска, не CD-ROM ISO.

Образ можно записать побайтно на отдельную флешку утилитой записи raw-образов. ВСЁ прежнее содержимое выбранной флешки будет уничтожено. Не выбирайте системный диск. BIOS-загрузка с USB в этом профиле не гарантируется; UEFI-загрузка зависит от firmware. После записи безопасно извлеките носитель.

По умолчанию ФС только для чтения. Команды:

```
ver
fs
help
unlock YES
write TEST.TXT "Hello from MultiPulti"
append TEST.TXT "Second line"
type TEST.TXT
lock
exit
```

UNLOCK — явное согласие на экспериментальную запись, НЕ признак сертифицированной стабильности. На единственном экземпляре важных данных запись не использовать. Исторические документы внутри образа относятся к прежним версиям; для профиля 0.22 главным является этот документ и START.TXT.

## Редактирование единого образа

MBR MP22: LBA 1–16 — stage2, LBA 17 — заголовок размера/CRC, LBA 18…2047 — ядро; FAT32 ESP начинается на LBA 2048. Файлы MULTIOS/KERNEL32.BIN и BLOADER.BIN в ESP — копии для просмотра, BIOS читает raw-сектора. Замена только файла KERNEL32.BIN НЕ обновляет BIOS-ядро.

В исходниках, на машине сборки с GCC/binutils, Python3, make, mtools и необходимыми стандартными заголовками:

```
python3 tools/build_bios_ntfs.py
make FS_PROFILE=profiles/filesystems-ntfs3g.mk uefi
python3 tools/build_bios_rw_image.py /path/original.img /path/updated.img --efi build/BOOTX64.EFI
```

Исходный образ — один из поставленных MP22 либо подготовленный MP11 с исправным MPSTORE/MPUNDO и чистым журналом. Укажите НОВОЕ имя выходного файла. Утилита не пишет на физические устройства, не заменяет исходник и отказывает при незавершённом журнале. Сначала восстановите журнал штатной загрузкой. Обновляются обе загрузки, контрольные суммы и SOURCES/PORTING.ZIP. Старый imagectl.py не поддерживает MP22 и для обновления ядра не применяется. Пара файлов должна происходить из одной сборки.

Цели make bios-rw и bios-rw-image добавлены отдельно. Обычные исторические make all/mkunified.py создают старый компактный профиль; для NTFS BIOS RW используйте только документированный расширенный путь. Полные соответствующие исходники, upstream-лицензии и NOTICE включены в архив; учитывайте GPL NTFS-3G при будущем распространении, исходный MIT не заменяет лицензии upstream.

## Проверки именно 0.22

- Реальный BIOS путь в эмуляторе: четыре модели CPU; DATA/ADS/hardlink/COPYADS, resize/write-at, rename, каталоги; проверка внешними ntfscat/ntfsfix.
- 40 выбранных точек отказа raw-write: постоянная I/O-ошибка или остановка процесса VM, затем новая BIOS-загрузка и проверка восстановления. Это модель, не физическое отключение питания накопителя.
- Загрузочные отказы при 16 МиБ, неверном CRC/размере; dirty/hibernated fixtures: отказ записи, SHA256 образа неизменен.
- Аллокатор: 50 000 случайных действий под ASan/UBSan; дополнительный аудит ISA. FAT32/exFAT BIOS smoke + внешние fsck.
- UEFI NTFS DATA/ADS/hardlinks; общий host-регрессионный набор трёх ФС. Host-тесты не подменяют проверки самостоятельной загрузки.

Для релизной стабильности ещё нужны физические платформы и накопители, проверки Windows/chkdsk, питание и flush/cache, расширенная матрица повреждений/объёмов/заполнения, отсутствующие NTFS-возможности и дополнительные драйверы накопителей. Обещания «все CPU», «все ПК» и «стабильная запись на любом диске» эта версия не даёт.
