# NTFS: этап 1 — метаданные и блочный интерфейс

**MultiOS 0.13-dev-ntfs1 / MultiPulti — vm2 studios | t.me/v2vproj**

НЕОПУБЛИКОВАННАЯ РАЗРАБОТКА. Это начало реализации, **не полноценная NTFS RW** и не Release 1.0. Запись NTFS в консоли по-прежнему запрещена.

## Реальный код этого этапа

### 1. Блочный интерфейс с 64-битным LBA

`include/multios/block64.h`, `lib/block64.c`:

- версия ABI, количество секторов и адрес LBA с 64-битными значениями;
- логический сектор 512/1024/2048/4096 байт;
- проверка границ сектора и диапазона байтов, переполнения смещений и неверного ABI;
- чтение произвольного диапазона через предоставленный вызывающим кодом буфер сектора;
- отдельные операции полного сектора и flush, без скрытой read-modify-write записи;
- ошибки read/write/flush и положительные неверные коды провайдера блокируют дальнейшую запись в данном экземпляре интерфейса;
- блокирование повторного bind: новый mount должен создавать новый контекст и отдельно проверять метаданные/восстановление.

NTFS использует этот интерфейс для чтения через **явный read-only адаптер старого HAL**. Адаптер отказывает адресам вне 32 бит, а не обрезает их.

**Ограничение:** глобальный HAL/VFS и Stream пока не мигрировали на 64 бита. Реальные диски больше 128 ГиБ, файлы больше 4 ГиБ и 4Kn NTFS этим этапом НЕ включены. Новый интерфейс с большими адресами и секторами проверен на синтетических провайдерах; существующие аппаратные драйверы остаются прежними.

### 2. USA/fixup codec

`lib/ntfs_meta.h`, `lib/ntfs_meta.c`:

- декодирование защиты секторных хвостов записей MFT/INDX;
- проверка формы и расположения Update Sequence Array;
- все защищённые хвосты проверяются **до изменения любого байта** буфера: ошибка позднего сектора не оставляет частично восстановленную запись;
- кодирование подготовленной записи в памяти: сохранение исходных хвостов в USA, обновление sequence number с пропуском зарезервированных значений, установка защиты в каждый сектор;
- проверка размеров 512..65536 байт при секторе 512..4096;
- NTFS-драйвер реально использует новый декодер при чтении MFT. Дополнительно проверяется, что USA не перекрывает FILE header/атрибуты.

USA защищает обнаружение несогласованных секторных частей записи. **Это не журнал, не транзакция и не обещание восстановления при отключении питания.** Кодирование само по себе не разрешает запись MFT на диск.

### 3. NTFS mapping pairs / runlist

- 64-битные VCN/LCN/длины, 1..8 байт на поле;
- положительные и отрицательные относительные LCN без signed-overflow;
- sparse runs с сохранением предыдущего физического LCN;
- sparse логическая длина не ошибочно ограничивается физическим числом кластеров;
- ограничение физической аллокации ёмкостью тома, проверка нулевых длин, терминатора, переполнений и capacity;
- декодирование и кодирование без изменения выходных данных при ошибке (вход/выход не должны перекрываться);
- NTFS-драйвер использует новый parser, затем проверяет сужение в прежние 32-битные структуры. Бесшумной потери старших битов нет.

Новый encoder работает только в памяти и тестовом harness, не вызывается командами записи ОС. Обработка split attributes и проверка глобального владения кластерами ещё отсутствуют: валидный runlist не означает безопасный RW-том.

### 4. Регрессии и независимая проверка

- 10 000 детерминированных roundtrip случаев runlist и 50 000 повреждённых/случайных входов, обычная сборка и ASan/UBSan;
- USA на секторах 512/1024/2048/4096, record sizes до 64 КиБ, повреждение каждого хвоста без частичной модификации;
- независимый mkntfs/libntfs-3g том: декодирование/кодирование MFT0 и MFTMirr0, проверка ntfsfix -n и совпадения содержимого четырёх потоков через ntfscat;
- общий FAT32/NTFS набор сохранён; тест переключения разделов исправлен: он больше не требует exFAT DATA у поставляемого FAT32-образа;
- список файлов standalone-компиляторов/профиля обновлён для новых модулей;
- переносимые исходники проверяются компиляцией для ARMv7/AArch64/RISC-V, без заявления о готовой загрузке на этих архитектурах.

Точные результаты текущего прогона — только `build/phase1-*`. Старые отчёты 0.12 не являются проверкой новых бинарников.

## Запуск тестов

```sh
make test-ntfs-meta test-block64
make all uefi multipulti
python3 tests/filesystems.py
python3 tests/ntfs_meta_volume.py
make test-filesystems-sanitize test-filesystems-faults
python3 tests/fat32_model.py
python3 tests/cross_compile.py
```

Нужны C toolchain, GNU-EFI, ASan/UBSan runtimes, dosfstools/mtools/exfatprogs, ntfs-3g/ntfsprogs с libntfs-3g для независимых fixtures, clang для cross-compile. NTFS-библиотека хоста не линкуется в ОС. На Debian/Ubuntu GNU-EFI пути отличаются: параметры — в START_HERE_RU.md.

- [ ] Валидатор/редактор атрибутов MFT и следование `$ATTRIBUTE_LIST`, sequence numbers и ссылкам на extension records.
- [ ] Настоящий обход/изменение I30 и Unicode-сравнение через `$UpCase`.
- [ ] Согласованные изменения `$Bitmap`, MFT, индексов и hard links, включая обновление зеркала по правилам NTFS.
- [ ] Разбор/восстановление и запись `$LogFile`, политика dirty/recovery, flush-порядок и тесты аварийной остановки на каждом этапе.
- [ ] Согласованная запись/создание/удаление/rename файлов и каталогов, изменение размеров, resident/nonresident переходы.
- [ ] Отдельные проверяемые контракты для ADS, security/ACL, sparse/compression, reparse и EFS; неподдерживаемое не игнорируется молча.
- [ ] Большая внешняя проверка совместимости и реальное железо.

FAT32/exFAT RW тоже остаются экспериментальными. Безопасная обработка повреждённых томов и аварийных сценариев для всех трёх ФС остаётся блокирующим условием Release 1.0.
