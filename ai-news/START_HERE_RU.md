# MultiOS / MultiPulti — начало работы

**vm2 studios | t.me/v2vproj**

НЕОПУБЛИКОВАННАЯ РАЗРАБОТКА. Это не Release 1.0 и не готовая замена Windows/MS-DOS.
В архиве один готовый образ `build/MultiOS-MultiPulti.img` (128 МиБ): BIOS i386 + UEFI x64, FAT32 для загрузки и FAT32 для пользовательских файлов. NTFS в этой версии — только чтение, не полноценная запись.

## Начать

1. Распакуйте архив целиком. Сохраните нетронутую копию образа.
2. Для безопасного первого запуска используйте QEMU: `./run-unified.sh bios` либо `./run-unified.sh uefi`. Нужны QEMU с машиной `pc`, OVMF для UEFI; пути смотрите в скрипте. Самой ОС Linux/Windows для работы не требуется: эти ОС нужны лишь для инструментов сборки/редактирования на компьютере разработчика.
3. `HELP` — команды; `VER` — версия; `FS` — текущая ФС; `FS DRIVERS` — встроенные файловые модули; `DIR`, `TYPE WELCOME.TXT` — просмотр.
4. Запись по умолчанию выключена. Для экспериментов на копии: `UNLOCK YES`, затем `MD DOCS`, `WRITE DOCS/a.txt "Hello"`, `TYPE DOCS/a.txt`, `LOCK`. На NTFS включить запись нельзя.
5. Экранная клавиатура: F2/Ctrl+O, стрелки + Enter. Схема из двух кнопок: NEXT и SELECT; PREVIOUS используется только в профиле с третьей кнопкой. Полная клавиатура работает при наличии соответствующего поддерживаемого драйвера.

## Редактирование без знания секторов

Инструменты пока для Linux/WSL: Python 3, `mtools`, `dosfstools`. Закройте ВМ перед редактированием. Не используйте физическое устройство вместо файла `.img`.

```sh
cp build/MultiOS-MultiPulti.img my-system.img
python3 tools/studio.py unpack my-system.img MyMultiOS
```

В `MyMultiOS` появится обычная папка:

- `files/` — файлы и папки пользовательского FAT32-раздела. Начните отсюда. Названия ASCII, без специальных символов; не более 16 уровней и 48 МиБ суммарно.
- `settings.ini` — настройки UEFI. Например, `osk=on` включает экранную клавиатуру, `osk=off` выключает. BIOS использует профиль сборки, не этот файл.
- `system/` — три готовых бинарника: `kernel32.bin`, `boot32.bin`, `bootx64.efi`. Без необходимости не меняйте.
- `.multios.json` — служебная опись. Не редактируйте.

Добавьте свой `files/HELLO.TXT`, затем:

```sh
python3 tools/studio.py plan MyMultiOS
python3 tools/studio.py apply my-system.img MyMultiOS --backup before-edit.img --yes
```

`before-edit.img` не должен существовать. Редактор сверяет исходный образ, делает полную резервную копию, пересоздаёт DATA в отдельном временном файле, проверяет FAT32 и атомарно заменяет образ. При ошибке до замены исходный образ остаётся прежним. Даты, атрибуты и короткие имена 8.3 при пересоздании DATA могут измениться; это не побайтовое сохранение метаданных. Папка `files/` становится полным содержимым DATA: удалённое из неё исчезнет в новом образе. Не применять к ценным данным.

После сохранения снова выполните `unpack` в НОВУЮ папку перед следующим изменением. Старая опись защищает от перезаписи изменившегося образа. `studio.py` намеренно не пересоздаёт NTFS/exFAT.

## Установка инструментов и пересборка

Пример для Debian/Ubuntu/WSL (готовому образу компилятор не нужен):

```sh
sudo apt update
sudo apt install python3 mtools dosfstools qemu-system-x86 ovmf
```

Для сборки добавьте `build-essential gcc-multilib binutils gnu-efi exfatprogs`. На Debian/Ubuntu обычно используются следующие GNU-EFI пути (проверьте их в своём дистрибутиве):

```sh
make all uefi multipulti EFILIB=/usr/lib EFILDS=/usr/lib/elf_x86_64_efi.lds EFICRT=/usr/lib/crt0-efi-x86_64.o
python3 tools/mkunified.py --data-fs fat32 --output build/MyMultiOS.img
```

На RPM-системах текущие defaults Makefile — `/usr/lib64`, GNU-EFI CRT/linker script в `/usr/lib64/gnuefi/`. На иных системах задайте EFIINC/EFILIB/EFILDS/EFICRT. Для NTFS-образа нужен `mkntfs` из ntfs-3g/ntfsprogs; для NTFS-fixture тестов также libntfs-3g с development headers. ARM/RISC-V здесь проверены только компиляцией переносимых объектов, не загрузкой.

`mkunified.py` никогда не перезаписывает существующий output. FAT32 и NTFS варианты можно создать из готовых бинарников. Для нового exFAT-варианта нужен exFAT-шаблон `build/multios.img`, создаваемый `make all`; поставляемый FAT32-образ им не является. Явно указывайте `--data-fs fat32`: исторический default builder — exFAT.

## Замена драйвера

Не переименовывайте исходник `.c` в `.drv`: он не станет исполняемым модулем. Сейчас модули статические: их можно заменить в исходниках и пересобрать. `MODULAR_0_12_RU.md` объясняет, какие 2 файла профиля менять и как установить готовый комплект. Динамического загрузчика драйверов пока нет.

## Флешка и реальные компьютеры

Образ содержит MBR/загрузчик, его записывают как **сырой образ всего носителя**, а не копируют `.img` как обычный файл. Такая запись уничтожит разметку и данные выбранного носителя: здесь она автоматически не выполняется. Сначала проверьте копию в ВМ. Оставшееся место большой флешки автоматически не расширяется. Secure Boot-подписи нет.

BIOS-версия пока видит только ATA primary master: возможность загрузчика прочитать ядро с USB через BIOS **не означает**, что ядро сможет работать с USB-накопителем после запуска. UEFI-версия использует протоколы прошивки и сохраняет Boot Services. На реальном USB-носителе поддержка зависит от прошивки; железо не сертифицировано. Не обещаем загрузку на любом x86/x64.

## Текущее состояние

FAT32 RW расширенно проверяется, но остаётся экспериментальным: нет журнала/гарантии сохранности при отключении питания. Полноценная NTFS RW, собственное post-UEFI x64-ядро, AHCI/NVMe/xHCI-драйверы хранения и массовая проверка оборудования ещё не готовы. Подробнее: `CHANGES_0_12_RU.md`, `MODULAR_0_12_RU.md`, `FILESYSTEMS_RU.md`.
