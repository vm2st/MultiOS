# MultiOS 0.24-dev-mirrororder — MultiPulti

vm2 studios | t.me/v2vproj. Неопубликованная разработка. НЕ стабильный Release 1.0.

## Исправленный дефект

В 0.23 заголовки частного undo-журнала всегда обновлялись в порядке «слот 0, затем слот 1». После прерывания один слот мог оказаться новее другого. При следующем восстановлении/транзакции перезапись снова начиналась со слота 0, даже если он содержал последнюю актуальную копию. Повторная авария могла создать разрыв поколений больше единицы; безопасный парсер затем отказывался открывать журнал. При единственном валидном слоте также существовал риск первым перезаписать именно его.

Дефект воспроизведён на исходниках 0.23 отдельным regression-тестом: восстановление, сбой после первого durable CLEAN, следующая транзакция, второй сбой после первого durable ACTIVE, ошибка открытия BAD. Это реальное исправление протокола, а не ослабление проверки повреждений.

## Что изменено

- При открытии запоминается, какой слот устарел/невалиден. Следующая запись ПЕРВОЙ заменяет этот слот, а не последнюю актуальную копию.
- Новая копия должна пройти flush и побайтное чтение-сравнение, прежде чем обновляется оставшаяся актуальная копия.
- Если обе копии совпадают, допускается прежний порядок 0→1. После полного успеха зеркало снова считается здоровым.
- При одной валидной копии сохраняется она; первая попытка замены идёт в повреждённый слот.
- Само открытие остаётся без записи. Для CLEAN-журнала с расходящимися/повреждёнными зеркалами команда FS показывает `degraded mirrors`. Это не автоматическое разрешение игнорировать другие повреждения.
- Проверка CRC, привязки к носителю, допустимых переходов и соседства поколений НЕ ослаблена. Уже испорченный журнал с разрывом >1 НЕ объявляется исправным и автоматически не «чинится».

Форматы MPUNDO1, MPSTORE1 и MP22 не меняются. Изменение общего слоя действует на FAT32, exFAT и NTFS как под BIOS, так и под x64 UEFI. Защиты readback/CRC и отказов ATA из 0.23 сохранены. Дополнительная полная копия данных/журнала не выделяется.

## Использование

В архиве три raw-образа с разделом данных NTFS, FAT32 или exFAT. Каждый содержит BIOS+UEFI. Сначала используйте копию в VM. Это не ISO.

```
ver
fs
help
unlock YES
write TEST.TXT "MultiPulti 0.24"
type TEST.TXT
lock
exit
```

RO по умолчанию и EXPERIMENTAL сохранены. UNLOCK YES не означает сертификацию. Ошибка во время commit означает неизвестный исход: после новой загрузки допустим целиком старый либо целиком новый результат. Не повторяйте изменяющие команды вслепую после ошибки. Сохраните образ и работайте с копией.

Если FS показывает degraded mirrors на CLEAN-журнале, имеется выбранная валидная копия. Открытие не ремонтирует её. Следующая разрешённая транзакция использует новый безопасный порядок. При BAD/BLOCKED не стирайте журнал, не меняйте CRC вручную и не отключайте защиту. Этот патч предотвращает новые цепочки дефекта, но не является инструментом спасения уже повреждённого журнала.

## Сборка/обновление

На машине сборки: GCC/binutils, стандартные заголовки, make, Python3 и mtools; upstream исходники/лицензии включены.

```
python3 tools/build_bios_ntfs.py
make FS_PROFILE=profiles/filesystems-ntfs3g.mk uefi
python3 tools/build_bios_rw_image.py /path/original.img /path/updated.img --efi build/BOOTX64.EFI
```

updated.img должен быть НОВЫМ файлом; исходник — поддерживаемый подготовленный образ с чистым согласованным журналом. Installer не пишет на физические устройства, не перезаписывает исходник и не обновляет незавершённый журнал. Сначала сделайте резервную копию. Замена только MULTIOS/KERNEL32.BIN не меняет raw-копию BIOS-ядра; используйте installer. SOURCES/PORTING.ZIP обновляется вместе с загрузкой. Старый imagectl.py не поддерживает MP22. C-модули статические, требуют пересборки. Исторический make all остаётся отдельным компактным профилем.

Побайтная запись образа на флешку уничтожает её прежнее содержимое. Не выбирайте системный диск. BIOS здесь требует минимум 32 МиБ RAM, E820/A20/EDD и IDE primary master (drive 80h); нативной BIOS USB Mass Storage поддержки нет. Для USB через UEFI требуется совместимый x64 firmware. UEFI сохраняет Boot Services.

## Тесты и границы

Новый тест перебирает каждую первую границу write/flush ограниченной транзакции и каждую следующую границу восстановления/начала новой транзакции, четыре модели сохранения и crash/I/O-error на втором сбое. Проверены low и >32-bit LBA. Отдельно выполняются 64 последовательных прерывания заголовков с двумя копиями либо с единственной валидной копией в каждом из слотов. Обычный и ASan/UBSan запуски не считаются разными уникальными сценариями.

Дополнительно выполняются цепочки остановок процесса настоящей BIOS-сборки на трёх ФС, прежние матрицы трёх ФС, silent-fault tests, BIOS/UEFI smoke и внешние fsck/NTFS-утилиты. Фактические PASS и счётчики — в отчёте.

Остаются ограничения: честные flush/read со стороны драйвера/firmware; CRC32 не криптографическая защита; нет гарантий против misdirected writes и лживого кэша. Только 512-byte/MBR, существующие пределы ёмкости, 4096 уникальных изменённых секторов операции. Нет BIOS AHCI/NVMe/USB Mass Storage, 8086/286/IA32 UEFI. BIOS clock — fallback 2000 UTC. Полная Windows NTFS ACL/SID/reparse/EFS/BitLocker/$LogFile/chkdsk не реализована; dirty/hibernated NTFS не разрешается RW. Тестов на реальном железе/питании и Windows chkdsk нет. Подробности базовых защит: WRITE_GUARD_0_23_RU.md. Первый публичный релиз по-прежнему только после критериев стабильного 1.0.
