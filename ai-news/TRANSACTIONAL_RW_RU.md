# MultiOS / MultiPulti — транзакционная запись FAT32/exFAT

**vm2 studios | t.me/v2vproj — UNPUBLISHED EXPERIMENTAL PATCH. Не Release 1.0.**

Это следующий этап после отдельного undo-модуля: журнал теперь подключён к реальным VFS-операциям и собирается в BIOS/UEFI. **Полной стабильной поддержки всех трёх ФС нет: NTFS writer по-прежнему отсутствует.**

## Что работает в новом профиле

Профиль `profiles/filesystems-journal.mk` включает общий адаптер `lib/storage_tx.c`. Целая операция создания, перезаписи, дополнения, копирования, переименования, удаления файла, создания/удаления каталога FAT32 или exFAT обёрнута в одну транзакцию. Все секторные записи этих операций идут через undo; прямой `disk_write` вне активной транзакции запрещён.

До чтения файловой системы при mount проверяется явный locator образа; незавершённая транзакция восстанавливается **до монтирования**. Без подготовленного журнала образ доступен только RO, без возврата к незащищённой записи. Защищается один выбранный MBR-раздел, а не ESP/загрузчик или весь диск.

- При обычной ошибке операции, включая переполнение журнала, выполняется откат. Mount после ошибки инвалидируется, чтобы не переиспользовать кэши выделения и каталогов. После успешного отката можно выполнить `mount auto` и затем `unlock YES`.
- При I/O-ошибке запись и дальнейший доступ через повреждённый контекст блокируются. Нужен перезапуск ОС/повторное открытие устройства; recovery выполняется на следующем mount. Команда `mount` не снимает аппаратную ошибку в текущем контексте.
- При ошибке commit результат неизвестен до повторного открытия: могло сохраниться старое или целиком новое состояние. Успех не сообщается.
- В `fs` и `df` видны состояние защиты и ограничение; режим остаётся EXPERIMENTAL.

## Жёсткие ограничения

1. **128 различных целевых секторов по 512 байт на одну операцию**, включая данные и метаданные, не «файл до 64 КиБ». Реальный предел полезных данных меньше и зависит от ФС/операции. Большая операция возвращает `NOSPACE` и откатывается. Автоматического разбиения с ложным обещанием атомарности нет.
2. Честный `flush` обязателен: он должен сохранять и упорядочивать предыдущие записи. На лживом контроллере гарантий нет. Тесты не доказывают стабильность на любом железе.
3. Один писатель, один выбранный раздел и один свободный слот MBR под журнал, HAL с секторами 512 байт и прежним ограничением адресации 32-bit LBA/128 GiB. Не GPT/EBR, не Secure Boot, не произвольная миграция существующих дисков.
4. NTFS остаётся RO с прежними ограничениями reader. Private undo — не NTFS `$LogFile`, writer или полноценный recovery NTFS. Не реализованы полные NTFS metadata updates, ACL/security, сжатие/EFS и другие необходимые пути записи.
5. Ограничения прежних FAT32/exFAT драйверов сохраняются. В частности, exFAT не получил автоматического расширения полного каталога; аудит и ограничения геометрии/имён/размеров по-прежнему могут отказать в RW. Это не «полная совместимость» с любым томом.
6. Профиль опциональный: обычный `profiles/filesystems.mk` сохранён как прежняя экспериментальная реализация, **без новой защиты**. Не путайте бинарники разных профилей. Динамической загрузки C-модулей нет.
7. Только одноразовые образы и резервные копии. Не устанавливать на рабочие носители и не хранить единственный экземпляр данных.

## Готовый образ

В подготовленном пакете `MultiOS-TX-EXPERIMENTAL.img` — один образ с BIOS i386-ядром, x64 UEFI live-приложением, FAT32 ESP, exFAT-разделом данных и отдельным хвостом журнала. UEFI по-прежнему использует Boot Services; это не новое нативное x64-ядро после ExitBootServices.

Начните с копии образа в эмуляторе. Например, QEMU:

```sh
qemu-system-x86_64 -machine pc -accel tcg -cpu qemu64 -m 32M \
  -drive file=copy.img,format=raw,if=ide,index=0 -serial stdio \
  -device isa-debug-exit,iobase=0xf4,iosize=0x04
```

BIOS-драйвер диска пока рассчитан на primary-master IDE/совместимое представление. В UEFI используется предоставленный прошивкой Block I/O. Новые аппаратные драйверы этим патчем не добавлены.

В консоли:

```text
fs
unlock YES
md TEST
write TEST/a.txt "hello"
append TEST/a.txt "second line"
copy TEST/a.txt TEST/b.txt
cmp TEST/a.txt TEST/b.txt
ren TEST/b.txt renamed.txt
type TEST/renamed.txt
del TEST/renamed.txt
lock
```

Если небольшая операция отказала без I/O и откат завершился, используйте `mount auto`, затем `unlock YES`. При аппаратном I/O-сбое не повторяйте записи: перезапустите тестовую ОС. Перед любыми внешними правками остановите ВМ и сделайте копию. Не редактируйте журнал вручную и не меняйте MBR/виртуальную геометрию образа: locator связан с ними. Большая физическая ёмкость поддерживается без расширения виртуальных разделов.

## Сборка из исходников

Linux, GCC/binutils с i386, GNU-EFI, Python 3, Make, dosfstools/mtools; для независимых проверок нужен exfatprogs. Для ASan/UBSan — runtime-библиотеки соответствующего компилятора.

```sh
make FS_PROFILE=profiles/filesystems-journal.mk all uefi
make test-storage-tx
make journal-image TX_OUTPUT=build/my-new-tx.img
```

`journal-image` сам пересобирает BIOS/UEFI с правильным профилем. Существующий выходной образ не перезаписывается. Для FAT32-раздела данных:

```sh
make journal-image TX_DATA_FS=fat32 TX_OUTPUT=build/my-fat32-tx.img
```

Подготовка копии своего **обычного MBR-образа** с поддерживаемым FAT32/exFAT-разделом:

```sh
python3 tools/prepare_journal.py source.img new-copy.img --partition 1
```

Это не установщик на диск: источник открывается только для чтения, выход создаётся исключительно новым обычным файлом. Устройства, symlink/hardlink источника, блокировки, существующий выход, перекрывающиеся разделы, GPT/EBR, повторная подготовка распознанного образа и NTFS отвергаются. Предварительная проверка не заменяет аудит ФС при `unlock`.

## Схема образа

Исходные данные копируются; в копии изменяется только свободная запись таблицы MBR: она помечает отдельную резервную область типом 0xDA. Источник не изменяется. После конца исходного файла добавляются 258 секторов undo-журнала (2 заголовка + 128 пар «дескриптор/исходные данные») и 2 идентичных неизменяемых locator-сектора. Существующие разделы не увеличиваются, свободные кластеры ФС под журнал не отбираются. Один свободный MBR-слот обязателен; четыре занятых слота приводят к отказу подготовки. Не форматируйте служебный раздел 0xDA в другой ОС.

Журнал находится через запись MBR, а не через последний физический сектор. Поэтому при корректном raw-копировании образа на поддерживаемый носитель большего размера устройство может сообщать большую ёмкость: адаптер ограничивает свой виртуальный диапазон исходной геометрией образа. Лишний физический хвост не используется. Это проверено синтетическим увеличением сообщаемой ёмкости; реальная USB-флешка на железе не испытывалась.

Locator: `MPSTORE1` @0; u32 version @8, sector_bytes @12; u64 total_sectors @16, journal_start @24, journal_sectors @32, data_start @40, data_sectors @48; media_id[16] @56; u32 partition_index @72, crc32 полного MBR @76; нули @80..507; crc32 байтов 0..507 @508. Два locator обязаны совпадать. Проверяются все MBR-разделы: служебный 0xDA обязан точно описывать журнал, а остальные — не пересекаться ни друг с другом, ни с ним. Совместимость с прежним явным footer-only форматом ограничена исходной точной геометрией образа.

Случайный media_id и CRC — привязка/контроль случайных повреждений, не криптографическая аутентификация. Внешние редакторы обязаны сохранять хвост. Исчезновение обоих locator не разрешает RW: профиль откажет в unlock.

## Что подтверждают тесты

Испытывается настоящий код FAT32/exFAT, VFS, HAL и undo, а не имитация файловых алгоритмов. Для восьми операций перебираются каждый write/flush, четыре ограниченные модели сохранения и два вида отказа (обрыв исполнения/возвращённая I/O-ошибка). Проверяется отсутствие смеси старого/нового состояния во всех секторах, которые стенд мог изменить, включая внешние по отношению к ФС области; journal-секторы исключены из сравнения пользовательского результата.

Дополнительно: переполнение 128 слотов с откатом, повторный сбой recovery, RO при необходимости recovery, повреждение locator/MBR, запрет обхода транзакции, 96 seeded-операций на каждую ФС, независимые fsck-проверки, сравнение FAT-данных через mtools и ASan/UBSan. Конкретные результаты и загрузочные проверки — в приложенном отчёте текущего патча.

Модель разрыва использует префикс 173 байта, а частичное сохранение — выбранное подмножество грязных секторов. Не перебраны все возможные повреждения, не выполнена сертификация реального железа. **Успех этих тестов не равен готовности стабильного Release 1.0.**
