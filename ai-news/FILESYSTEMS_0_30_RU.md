# MultiOS 0.30-dev-fat32active / MultiPulti

Неопубликованная разработка. Не стабильный Release 1.0. FAT32, exFAT и NTFS доступны для экспериментальной записи; полная совместимость форматов не заявляется.

## Новая совместимость FAT32

Добавлена поддержка `BPB_ExtFlags` с отключённым зеркалированием: можно читать и изменять корректный том, где активна FAT0 либо FAT1, а другая таблица устарела. Поддерживается и том с одной FAT.

До исправления native mount выбирал правильную FAT, но последующий FatFs read-view использовал FAT0. Чтение файла с несколькими кластерами на томе с активной FAT1 могло завершаться ошибкой. Unlock таких томов блокировался. Оба случая воспроизведены тестами на прежнем коде.

Теперь:

- Независимый FAT32 parser передаёт проверенную раскладку адаптеру FatFs.
- После вычисления полной геометрии FatFs выбирается только активная таблица; начало DATA не смещается. Upstream FatFs не изменён.
- При отключённом зеркалировании неактивная FAT не проверяется на равенство и не синхронизируется. При включённом зеркалировании прежняя проверка равенства сохранена.
- Неверный индекс активной таблицы, неподдержанные резервные флаги, несогласованная резервная boot sector и конфликт зеркальных FAT не разрешают запись.
- Возможность относится к расширенному FatFs-профилю. Компактный legacy writer по-прежнему не открывает nonmirrored FAT32 RW.

## BIOS и UEFI

В этой поставке пересобраны **оба** бинарника: freestanding BIOS i386 и UEFI x64. Они используют текущие адаптеры FAT32/exFAT/NTFS-3G, включая исправления ошибок и unlock из 0.29. EFI от старой 0.26 больше не используется в новых образах.

Это не означает одинаковые драйверы устройств:

- BIOS: собственные ATA либо USB BOT через UHCI/OHCI/EHCI; EDD нужен загрузчику.
- UEFI: приложение использует firmware console/Block I/O и сохраняет Boot Services. Это не нативный post-ExitBootServices x64 USB-драйвер. Работа через emulated xHCI в UEFI относится к firmware, а не к собственному xHCI-драйверу MultiOS.

## Что находится в архиве

- `images/MultiOS-0.30-usb-fat32.img`, `-exfat.img`, `-ntfs.img` — три альтернативных raw-образа с FAT32 ESP, DATA выбранной ФС и private undo. Выберите один.
- FULL-SOURCES — весь текущий код ядра, драйверов, библиотек и тестов.
- `bios-bundle/`, `uefi-bundle/` — согласованные бинарные сборки.
- `tools/` — настройщик и INI-профили.
- `TEST_FS_0_30_RU.md`, `reports/`, `SHA256SUMS` — проверки и контрольные суммы.

## Запуск

1. Сохраните резервную копию флешки. Запишите один `.img` побайтово, например Rufus DD. Запись уничтожает прежнюю разметку и данные в диапазоне образа.
2. В BIOS/CSM нужны EDD и поддержанный контроллер. В UEFI запускается `EFI/BOOT/BOOTX64.EFI`; для неподписанного образа обычно требуется отключённый Secure Boot либо собственная доверенная подпись. Установка ключей и подписание этой поставкой не выполняются.
3. В консоли: `ver`, `modules`, `fs`; для native BIOS USB дополнительно `usb`. Версия — `0.30-dev-fat32active`.
4. На расходной копии:

```text
unlock YES
md DEMO
write DEMO/HELLO.TXT "Hello MultiOS"
append DEMO/HELLO.TXT "second line"
copy DEMO/HELLO.TXT COPY.TXT
cmp DEMO/HELLO.TXT COPY.TXT
resize COPY.TXT 8193
writeat COPY.TXT 509 "PATCH"
sync
lock
```

В BIOS команда `exit` завершает работу ядра, а `poweroff` зависит от платформенного драйвера. В UEFI доступен firmware poweroff. Не извлекайте системный USB-носитель во время работы.

Настройка ATA для IDE primary master:

```sh
python3 tools/customize.py images/MultiOS-0.30-usb-fat32.img --settings tools/ATA.INI --output MultiOS-ATA.img
```

Настройки OSK и двух/трёх кнопок описаны в сохранённых `USB_STORAGE_0_28_RU.md` и руководствах ввода. C-модули требуют пересборки; выбор встроенных модулей выполняется настройщиком. Не меняйте только KERNEL32.BIN архиватором: BIOS использует согласованную raw-копию с CRC.

## Сборка

Распакуйте FULL-SOURCES рядом с `images/` и `tools/`. Нужны GCC/binutils, make, Python3, mtools; GNU-EFI runtime собирается из приложенного upstream-архива. Расширенный BIOS-профиль собирается отдельно:

```sh
cd MultiOS
make bios-rw
make FS_PROFILE=profiles/filesystems-ntfs3g.mk uefi
python3 tools/build_bios_rw_image.py ../images/MultiOS-0.30-usb-fat32.img ../rebuilt-ata.img --efi build/BOOTX64.EFI
python3 tools/customize.py ../rebuilt-ata.img --settings ../tools/USB.INI --output ../rebuilt-usb.img
```

Installer принимает только новый выходной файл и штатно подготовленный образ с чистым журналом. Он не является установщиком на произвольный физический диск. Обычный `make all` использует другой компактный профиль.

## Оставшиеся ограничения

Поддержка active FAT32 не означает реализацию всех вариантов FAT32/exFAT/NTFS. По-прежнему: 512-байтовые секторы в адаптерах, ограничения размера/геометрии HAL и audit workspace, конечный private undo до 4096 изменённых секторов на операцию. Большие копии выполняются staged copy; это копирование DATA, не полное клонирование всех NTFS-метаданных.

Нет полного NTFS ACL/reparse/EFS/$LogFile интерфейса и восстановления любого грязного/гибернированного тома. Нельзя снимать соответствующие защитные отказы. Для BIOS USB отсутствуют xHCI, хабы, split, UAS, multi-LUN и 4Kn; на одном host выбирается одно direct device. Не гарантируется запуск на любом x86/x64, 8086/286 не поддерживаются. Реальное железо, физический power-cut и Windows chkdsk не проверены.
