# MultiOS 0.10-dev — аудит неблагоприятных сценариев

**MultiPulti · vm2 studios | t.me/v2vproj · UNPUBLISHED DEVELOPMENT**

Это набор исправлений и проверок, а не обещание «исправлены все ошибки» и не
стабильный Release 1.0. Физическое оборудование по-прежнему не испытано.

## Исправления

| № | Проблема / изменение | Результат |
|---|---|---|
| 01 | Длина exFAT могла выходить за объявленную MBR partition | Mount ограничен и диском, и выбранным разделом |
| 02 | Не проверялась резервная boot region | Проверяются обе checksum regions и совпадение геометрии; несовпадение — отказ, без автоматического ремонта |
| 03 | Непроверенные MustBeZero/PercentInUse | Некорректные поля отклоняются |
| 04 | Вычисление ёмкости FAT через умножение могло переполниться | Заменено проверкой необходимого числа секторов через деление |
| 05 | UNLOCK не проверял принадлежность кластеров | Новый ограниченный write preflight: root/bitmap/upcase/files/directories, FAT/NoFatChain, bitmap used bits |
| 06 | Кластеры могли одновременно принадлежать файлу и root/метаданным/другому файлу | Повторное владение запрещает запись |
| 07 | Ссылки на свободные кластеры, циклы, короткие/длинные FAT chains | Проверяются перед UNLOCK; неверный EOC/extent отвергается |
| 08 | Неподдержанные entries/размеры могли остаться незамеченными до записи | Для write preflight действуют строгие правила; сомнительный том остаётся RO |
| 09 | Обход каталога с cursor+32 мог переполниться | Проверки вычитанием, выравнивание и диапазон cursor; корректность directory size/VDL |
| 10 | Нулевой read с NULL и некорректные параметры внутренних API | Нулевой read не делает арифметику NULL; неверные VDL/mode/source отвергаются |
| 11 | Создание каталога за пределом собственного audit-depth | MD depth 17 отклоняется до изменения диска; глубина 16 проверена после повторного UNLOCK |
| 12 | Ошибка SYNC/LOCK/flush могла оставить RW активным | HAL фиксирует poisoned/RO; последующие низкоуровневые записи также блокируются |
| 13 | Положительный error-code нарушившего ABI драйвера мог выглядеть успешным | Ненулевой положительный ответ read/write/flush нормализуется в IO |
| 14 | POSIX harness мог зависнуть при открытии FIFO | Nonblocking open + проверка regular file; hardlinks/symlinks запрещены |
| 15 | Harness не участвовал в POSIX record locks QEMU | Добавлены record locks дополнительно к flock; проверены read/write конфликты |
| 16 | imagectl мог валидировать одни байты, а затем прочитать другие для установки | Ограниченный одноразовый source snapshot; raw kernel и FAT mirror получают одинаковые байты |
| 17 | install мог читать слишком большой файл / FIFO | Размер ограничен до чтения; nonblocking/no-follow regular-file проверка |
| 18 | mtools редактировал ESP прямо внутри целого образа | Запись идёт в отдельный 64 MiB ESP snapshot; fsck.fat -n до/после; возвращается только фиксированный диапазон ESP |
| 19 | Изменения hardlink/ctime во время transaction не проверялись | Перед заменой сверяются identity/size/mtime/ctime/link count; лишние MBR partitions отвергаются |
| 20 | Повторная сборка fault-test image отказывалась перезаписывать старую фикстуру | Сборка через новый .tmp и замена тестового файла, по аналогии с основной build-целью |

Пять классов дефектов воспроизведены на предыдущем 0.9 host: короткий раздел,
повреждённая backup checksum, root cluster отмечен свободным, file/root crosslink,
file/file crosslink. В baseline-прогоне команды записи не выполнялись.

## Новые границы записи — намеренно консервативные

- До **65536 кластеров**, **16 уровней каталогов**, **32768 directory records**
  на один preflight. Это программные лимиты, не гарантия времени на неисправном I/O.
- Читаются поддержанные тома большего размера; UNLOCK за пределами проверки
  возвращает unsupported, а не включает потенциально небезопасную запись.
- Если дерево содержит Unicode/неподдержанный allocation entry/размер, запись
  не включается. Это ограничение write subset, не исчезновение данных с диска.
- Дополнительно выделенные, но не принадлежащие поддержанным entries кластеры
  **не освобождаются и не используются повторно**. Чистый exfatprogs-том может
  содержать такие резервирования. Изначальный строгий equality-check нашёл
  регрессию на внешнем формате; исправление сохраняет резервирования, а не
  ослабляет проверку referenced-but-free или crosslinks.
- Preflight не является полным fsck, не исправляет том и не проверяет абсолютно
  все семантические поля, имена/дубликаты/временные метки или намеренно враждебные
  комбинации. Например, полный поиск дубликатов имён не добавлен.

## Проверки и воспроизведение

```bash
QEMU=/path/to/legacy-pc-qemu make test
make test-hardening
QEMU=/path/to/legacy-pc-qemu make test-kernel-faults
```

Новые отчёты `build/dev10-*`: adverse-volume, mutation, host-safety,
exfat-bounds, io-failure, flush-fault, write-limits, baseline-reproduction.
Мутационный прогон — 256 детерминированных однобайтных изменений с ASan/UBSan;
это ограниченная кампания, не исчерпывающий fuzzer. Adverse fixtures — 22 отказа
без изменения диска, плюс valid write/re-open/fsck и сохранение reserved bits.
Ошибки flush — синхронная инъекция в четыре WRITE barriers и отдельно SYNC/LOCK.

В POSIX host режимы fault injection доступны только при сборке с
`MULTIOS_FAULT_INJECTION`. Они не включены в обычную поставляемую программу и
не добавляют аварийных команд в BIOS/UEFI.

Для редактора образа теперь нужны Python 3, mtools и **fsck.fat (dosfstools)**.
Проверки FAT выполняются с `-n`: никакого автоматического исправления.

## Что остаётся риском

Внезапное питание/torn sectors/кэши контроллеров, journal/recovery, DMA и порча
RAM, одновременный writer, игнорирующий advisory locks, зависший аппаратный bus,
плохие прошивки, непроверенные устройства и новые разновидности повреждений.
Часть ошибок остановит ОС, но не восстановит данные. Native USB остаётся Intel
UHCI; OHCI/EHCI/xHCI, hubs/storage и подтверждённый reconnect не добавлены.

Нет paging/memory isolation, native x64 после ExitBootServices и универсального
BIOS INT13 bridge. exFAT RW всё ещё экспериментален: только ненужные копии образов,
резервные копии и read-only по умолчанию. Называть эту версию стабильной 1.0 нельзя.
