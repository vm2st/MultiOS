# NTFS: этап 2 — списки атрибутов и дополнительные записи MFT

**MultiOS 0.14-dev-ntfs2 / MultiPulti — vm2 studios | t.me/v2vproj**

НЕОПУБЛИКОВАННАЯ РАЗРАБОТКА. Не Release 1.0. Это расширение собственного NTFS-драйвера на C, **не полная NTFS и не NTFS RW**. Установленная в среде разработчика libntfs-3g используется только независимыми тестами, в BIOS/UEFI/host-бинарники MultiOS не включается.

## Отчёт по изменениям

1. **Отдельный проверяемый модуль атрибутов** — `lib/ntfs_attr.h/.c`. Итераторы resident/nonresident FILE attributes и `$ATTRIBUTE_LIST`; длины, смещения, выравнивание, границы значений/UTF-16 имён, заголовки sparse/compressed. Sequence number и номер MFT разделены; VCN/ref не обрезаются молча. При ошибке/end cursor и результат остаются нетронутыми. API требует уже USA-декодированный FILE record и неперекрывающиеся буферы результата/входа.
2. **Resident `$ATTRIBUTE_LIST`** — чтение точного размера значения и полная структурная проверка списка до переходов по ссылкам.
3. **Nonresident `$ATTRIBUTE_LIST`** — чтение ограниченного списка через проверенные mapping pairs. Sparse-список и разделённый по нескольким атрибутам сам список не поддержаны.
4. **Unnamed DATA в extension records** — проверяются in-use, sequence number, соответствие directory flag, номер/sequence базовой записи и instance ID атрибута. Нельзя подставить запись другого файла или проигнорировать отсутствующий базовый DATA. Вложенные списки дополнительных записей отвергаются.
5. **Несколько DATA-экстентов одного потока** — сборка общей карты при непрерывных VCN; пробелы/перекрытия/дубликаты, неполная карта, выход физических кластеров за том и неверный HighestVCN отвергаются. Sparse DATA и обнуление неинициализированного хвоста сохраняются.
6. **Resident DATA больше не держит указатель на перезаписываемый MFT-буфер** — значение копируется в рабочий snapshot. Перед чтением заново проверяются действительные size/initialized.
7. **Регистрация модулей/сборки** — новый файл включён в профиль файловых систем, BIOS i386, UEFI x64, host и отдельные fault/cross-компиляции; зависимости заголовка добавлены в Makefile. ABI профиля ФС не менялся.
8. **Дополнительная проверка каталогов** — root/переданный каталог должны быть базовыми MFT-записями, а не extension record.
9. **Независимые тесты** — libntfs-3g переносит resident DATA в extension record, формирует nonresident список, а отдельный test-only C helper делит DATA на две MFT-записи без изменения содержимого/аллокации. ntfsinfo/ntfscat проверяют результат независимо от кода MultiOS. Тесты отказываются работать с блочными устройствами.
10. **Один готовый образ и инструкция** — прежняя редактируемая схема FAT32 ESP + FAT32 DATA сохранена; внутри ESP `DOCS/NTFS2.MD` и актуальный `SOURCES/PORTING.ZIP`. Тестовые NTFS-образы создаются тестами, не поставляются как дополнительные готовые ОС.

## Как проверить самостоятельно

Нужны компилятор C, Python 3, ntfsprogs/ntfs-3g и development headers (`ntfs-3g-dev` либо `ntfs-3g-devel`), ASan/UBSan. GNU-EFI/QEMU нужны только соответствующим сборкам/boot-тестам.

```sh
make all uefi multipulti
make test-ntfs-meta test-block64 test-fs-registry test-ntfs-attr
make test-ntfs-attrlist
make test-ntfs-stream
make test-filesystems-sanitize test-filesystems-faults
python3 tests/cross_compile.py
# ВМ: укажите QEMU с machine pc для BIOS; QEMU_UEFI отдельно для UEFI.
QEMU=qemu-system-x86_64 python3 tests/ntfs_attrlist_boot.py
```

`test-ntfs-attrlist` создаёт собственный временный обычный образ `build/ntfs2-tests/attributes.ntfs`. Проверяются шесть потоков по CRC32 относительно ntfscat, запрет NTFS-записи и неизменность источников. Два DATA-экстента занимают VCN 0..79 и 80..159. В normal и ASan/UBSan сборках проверяются повреждения sequence/base references, ID, VCN, USA, длины/имени списка, mapping pairs, пропущенных DATA и nonresident-list bounds. Санитарный VFS harness проверяет 63 комбинации смещения/длины, включая одно невыровненное чтение через границу двух экстентов и отказ за EOF без порчи буфера. Отдельный parser test проверяет 50 000 повреждённых/случайных record/list входов.

Готовый образ: `build/MultiOS-MultiPulti.img`. Для обычного первого запуска — `START_HERE_RU.md`. На NTFS: `FS`, `DIR`, `TYPE resident.txt`, `CRC32 split.bin`; `UNLOCK YES` и изменение файлов **намеренно запрещены**.

## Результат текущего прогона

- Новый attribute parser: 50 000 hostile record/list входов, normal + ASan/UBSan.
- Интеграция списков: 227 проверок, 26 повреждённых томов, normal + ASan/UBSan; 63 VFS offset/bounds комбинации.
- BIOS i386/486 и UEFI x64/OVMF читают независимые extension-DATA fixtures; NTFS-запись отклонена, исходные данные неизменны.
- Сохранены 164 FAT32/NTFS assertions; 160 mutation runs под ASan/UBSan; 8-ГиБ sparse FAT32 image с fsck; 19 synchronous fault positions.
- FAT32 модель: 192 операции, 328 сравнений/checkpoints, 16 fsck checkpoints. exFAT: 44 основных assertions, 32 edge и 48 fault assertions.
- Переносимые объекты: по 16 для ARMv7/AArch64/RISC-V, только компиляция. Готовых портов этих платформ не появилось.
- Редактор образа: 16 tool invocations; BIOS → UEFI → BIOS FAT32 обмен и независимый fsck. Структурный i386/canary/exception audit пройден, но не является доказательством отсутствия ошибок.

Точные журналы вложены как `build/phase2-*`. Исторический `NTFS_STAGE1_RU.md` описывает прошлый этап, а не отсутствие новых DATA-экстентов.

## Что остаётся ограниченным

- NTFS только чтение. Нет создания/удаления/переименования/записи, согласованного обновления MFT/bitmap/index, транзакций `$LogFile`, replay/rollback, обработки USN и ACL/security как полноценного системного сервиса.
- Поддерживаются DATA-ссылки списков. Перенесённые `$FILE_NAME` не объединяются для перечисления каталогов; ADS не доступны через VFS; индексы `$I30`/B+tree не заменены — остаётся ограниченный MFT scan. Список атрибутов начального `$MFT` не поддержан.
- Не более 16 КиБ на `$ATTRIBUTE_LIST`, 32 DATA-атрибутов и суммарно 32 runs; 64К MFT-записей, FILE record не более 4096 байт. Превышение даёт отказ, не «полную поддержку». Полностью resident/пустые потоки разрешены; compressed/EFS/reparse — не реализованы.
- Внутренние новые codecs понимают 64-битные поля, но действующий HAL/VFS остаётся 32-битным: NTFS 512-byte sectors, диск до 128 ГиБ и поток до 4 ГиБ. 4Kn и большие тома не включены.
- Имена за пределами ASCII показываются с предупреждением; полной Unicode-адресации/case folding нет. Static single-volume workspace, не reentrant и не многопоточный драйвер.
- BIOS — собственное i386-ядро с текущими ограничениями драйверов; x64 UEFI — firmware app с Boot Services, не post-firmware x64-ядро. Тесты ВМ не являются сертификацией реального оборудования/внезапного отключения питания.
- FAT32/exFAT этим этапом не переписывались: их запись остаётся экспериментальной. Полная стабильная поддержка всех трёх ФС остаётся обязательной работой перед 1.0.

## Следующие блокирующие этапы

1. Полный 64-bit HAL/VFS и перенос аппаратных провайдеров, большие/4Kn тома.
2. Bootstrapping `$MFT` со списками атрибутов, индексы каталогов и полноценные имена; общая проверка метаданных/владения кластерами.
3. Модель NTFS-транзакций и recovery с fault-injection на каждой операции до включения дисковой записи; затем согласованные операции создания/изменения/удаления.
4. Проверки совместимости независимыми реализациями и сценариями crash/power-loss. Только после этого обсуждать stable Release 1.0.
