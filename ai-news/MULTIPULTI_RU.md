# MultiPulti — собственное лёгкое ядро MultiOS

> Текущий снимок: **0.11-dev, не опубликован**. Первая публичная версия — только
> стабильный **Release 1.0**. См. RELEASE_POLICY_RU.md и TWO_BUTTONS_RU.md.

**vm2 studios — t.me/v2vproj. Автор модульного шаблона портирования.**

Ветка BIOS действительно стартует без Windows/Linux/DOS: собственный MBR,
переход в protected mode, startup и freestanding C-код. Входная точка C теперь
`multipulti_main`. Экспорт сборки: `build/MultiPulti32.bin` (`make multipulti`).
Это не Linux-дистрибутив и не оболочка, запущенная поверх DOS.

Сейчас MultiPulti — **экспериментальное минимальное ядро**, не законченная ОС.
Оно включает HAL, менеджер статических драйверных модулей, консоль/OSK, exFAT
и команды. Пока нет IDT/обработчиков исключений общего назначения, управления
виртуальной памятью, scheduler/процессов, загрузчика программ и системных вызовов.
Маленький binary не означает, что эти функции уже существуют.

## CPU и устройства — разные уровни

Собственный kernel компилируется для набора инструкций **i386**, без SSE/MMX,
и может работать в 32-битном режиме подходящих x86-64 систем с BIOS/CSM. Проверки
выполняются на эмулируемых 486 и qemu64. 8086/8088/286 не поддерживаются.
32-битный protected-mode бинарник не является нативным x86-64 kernel.

UEFI x64 target в этой версии сохраняет Boot Services: аппаратные контроллеры
обслуживает прошивка. Он использует общий C-core, но не запускает BIOS MultiPulti32
и не становится native64 только благодаря имени MultiPulti в приветствии.
Для собственного post-ExitBootServices x64-ядра ещё нужны загрузочный протокол,
карта памяти, GDT/IDT, paging, аллокатор и свои драйверы ввода/накопителей/экрана.

На **каждом** x86/x64 обещать запуск нельзя: даже один CPU встречается с разными
прошивками, режимами загрузки, видеовыходами, контроллерами и периферией. Цель
проекта — расширять подтверждённые комбинации CPU+плата+драйвер, а не подменять
проверку универсальной надписью. Новые готовые драйверы интегрируются через
профили; неизвестному железу нужен аппаратный код, не только конфиг.

## Один образ

`ONE_IMAGE_RU.md` описывает 128 MiB образ с BIOS MultiPulti32, UEFI-приложением,
общим exFAT, конфигом и исходниками. Его редактор сохраняет данные при обновлении
собранных компонентов. Новые C-драйверы по-прежнему компилируются вне системы;
инструмент не является встроенным компилятором или загрузчиком внешних модулей.

Для native-ветки сейчас используется IDE primary master. Проверка MBR disk ID
помогает не открыть другой внутренний exFAT при загрузке с неподдержанного носителя;
она не превращает ATA в USB и не отличает клоны с одинаковой подписью. Для USB
используется UEFI firmware path, пока нет собственного USB-host стека.

Оригинальный код — MIT: vm2 studios (t.me/v2vproj) и участники проекта.
Обязательные авторские уведомления GNU-EFI сохранены, его авторство студии не
приписывается. В собственных исходниках есть credit header, а в системе —
команды `CREDITS`, `ABOUT`, `VER`, `MODULES` и `MULTIOS/BRAND.TXT` на boot-разделе.
