# Файловые системы: Unicode-пути и проверка совместимости

**MultiOS 0.16-dev-unicode / MultiPulti — vm2 studios | t.me/v2vproj**

**НЕ ОПУБЛИКОВАНО. Не Release 1.0.** Это крупное расширение собственного C-кода, но **не полная реализация NTFS/FAT32/exFAT**. NTFS остаётся только для чтения; запись FAT32/exFAT экспериментальная и выключена при загрузке.

## Отчёт по каждому изменению

1. **Общий Unicode-кодек.** UTF-8 ↔ UTF-16, BMP и surrogate-пары для символов вне BMP. Отвергаются overlong UTF-8, незаконченные последовательности, surrogate-коды в UTF-8, одиночные UTF-16 surrogate и значения выше U+10FFFF. При ошибке кодека выходной буфер/счётчик не становятся частично готовым результатом.
2. **VFS.** Путь внутри ядра — UTF-8. Кириллица, греческие символы, CJK и emoji больше не заменяются вопросами в имени. Каталоги TREE и поиск используют полное корректное имя, а не усечённое отображение. Короткие ASCII-алиасы FAT32 сохранены.
3. **Файловый ABI 3.** Каждый модуль предоставляет `name_equal(a,b)` с результатом 1/0/ошибка. Политика сравнения и ошибки чтения таблицы регистра принадлежат драйверу ФС, а не зашиты в VFS. ABI 1/2 отвергаются. Все статические модули нужно пересобрать вместе; это не горячая замена бинарных `.drv`.
4. **FAT32/VFAT: чтение.** Длинные имена декодируются из UTF-16 с проверкой порядка LFN, checksum, padding и surrogate-пар. Неподдерживаемое длинное имя не превращается в другой адресуемый файл.
5. **FAT32/VFAT: запись.** Создание файлов и каталогов, overwrite, append, copy, rename, delete/rmdir принимают Unicode-имена. Число LFN-записей рассчитывается в UTF-16 units, не в байтах UTF-8; emoji занимает два units. Сохраняются preflight владения кластерами, проверки FAT-зеркал, read-only атрибутов и блокировка после ошибок записи.
6. **FAT32: регистр.** Фиксированная BMP upcase-политика из уже поставлявшейся `tools/upcase.bin`: 874 неединичных пары, двоичный поиск, без locale/Unicode-библиотеки ОС-разработчика. Это не универсальная поддержка OEM code pages и не обещание совпадения со всеми версиями Windows.
7. **exFAT: настоящая таблица регистра.** Разбирается compressed/uncompressed Up-case Table тома, проверяются checksum, размер, нулевые/выходящие за диапазон identity runs, полнота покрытия, ASCII и surrogate-отображения. Индекс на каждые 256 units и секторный кэш занимают около 2,5 КиБ, вместо новой постоянной таблицы на 128 КиБ.
8. **exFAT: Unicode NameHash.** Хеш вычисляется по старшему и младшему байту UTF-16 после отображения таблицей именно этого тома. Проверяются не только ASCII-имена. Количество вторичных C1-записей и NameLength также считаются в UTF-16. Unicode поддерживается в доступных операциях RW, а не только в DIR.
9. **NTFS: Unicode-чтение.** FILE_NAME преобразуется в UTF-8. Поиск без учёта регистра использует реальный `$UpCase` тома с секторным кэшем. Проверяются длина/initialized таблицы и обязательные ASCII-отображения; при remount кэш сбрасывается. Поддержка resident/nonresident, sparse/uninitialized данных и ранее добавленных ATTRIBUTE_LIST/extension records сохранена в прежних границах.
10. **Редактор команд.** UTF-8 вводится целыми символами; LEFT/RIGHT, Backspace и Delete не разрезают многобайтный символ. History принимает UTF-8. Некорректная/незаконченная UTF-8 строка не исполняется после молчаливого удаления байтов. Ctrl+C сбрасывает строку. Ограничение — 511 байт.
11. **UEFI input.** SimpleTextInput CHAR16 кодируется в UTF-8 byte events, включая surrogate-пару. Unicode-код 0x0101 больше не путается с событиями навигации, которые лежат вне диапазона байта.
12. **Вывод.** UEFI text/plain декодируют UTF-8; экранные ячейки UEFI хранят CHAR16, scroll/clear учитывают их размер. BMP-глифы зависят от прошивки; символы вне BMP отображаются `?`. BIOS VGA без Unicode-шрифта тоже показывает один `?` на не-ASCII символ, но COM1 передаёт исходный UTF-8. Само имя/данные от этого не меняются.
13. **Безопасность и совместимость.** Добавлены отдельные исчерпывающие тесты кодеков, Unicode-операций ФС, изменённых таблиц регистра, повреждённых имён и UEFI protocol mocks. Сторонние инструменты используются только как тестовые оракулы на компьютере разработчика: в собственный драйвер они не встроены.

## Как попробовать

Готовый единый образ: `build/MultiOS-MultiPulti.img`, 128 МиБ. В нём FAT32 ESP и FAT32 DATA. Запуск на копии — `./run-unified.sh bios` или `./run-unified.sh uefi`; QEMU/OVMF устанавливаются отдельно. Собственное BIOS-ядро работает без посторонней ОС внутри ВМ. UEFI-вариант сохраняет Boot Services и ещё не является собственным post-UEFI x64-ядром.

Для UTF-8-команд удобен последовательный терминал либо host harness; harness — **только тест**, не самостоятельное ядро. UEFI firmware keyboard может передавать Unicode, если прошивка/раскладка умеет. Родные PS/2/USB-HID раскладки и экранная клавиатура пока ASCII; русскую раскладку и Unicode-picker в OSK этот этап не добавляет. Двухкнопочные NEXT/SELECT и опциональный PREVIOUS не изменены.

```text
VER
FS DRIVERS
UNLOCK YES
MD Документы
WRITE Документы/Привет.txt "Hello from MultiPulti"
TYPE ДОКУМЕНТЫ/ПРИВЕТ.TXT
COPY Документы/Привет.txt Документы/Копия.txt
REN Документы/Копия.txt "Новое имя.txt"
CMP Документы/Привет.txt "Документы/Новое имя.txt"
TREE
STAT64 Документы/Привет.txt
HEXAT Документы/Привет.txt 0 8
DEL "Документы/Новое имя.txt"
LOCK
```

Текст TYPE/READAT по-прежнему безопасно фильтруется как ASCII/binary viewer; поддержка Unicode **имён** не означает полноценный UTF-8 текстовый редактор. HEXAT показывает точные байты. На NTFS `UNLOCK YES` должен завершиться отказом; это правильно.

## Проверки и воспроизведение

На Linux/WSL нужны C toolchain, GNU-EFI, mtools/dosfstools, exfatprogs, ntfsprogs/отдельная libntfs-3g для fixture generation; для загрузочных тестов QEMU/OVMF. Список зависимостей и установка — `START_HERE_RU.md`.

```sh
make all uefi multipulti
make test-unicode test-editor test-uefi-unicode test-fs-registry test-file64-epoch
python3 tests/unicode_filesystems.py
MULTIOS_HOST="$PWD/build/multios-sanitize-host" python3 tests/unicode_filesystems.py
python3 tests/unicode_metadata.py
make test-filesystems-sanitize test-filesystems-faults
python3 tests/fat32_model.py
make test-ntfs-meta test-block64 test-ntfs-attr test-ntfs-attrlist test-ntfs-stream
make test-file64
python3 tests/unicode_boot.py
```

Перед sanitizer-командой отдельно соберите `make build/multios-sanitize-host`. BIOS-загрузочные тесты требуют QEMU с машиной `pc`; путь можно передать через `QEMU`. UEFI использует `QEMU_UEFI` и OVMF. Не все варианты пакета QEMU включают legacy PC.

- В каждом из normal и ASan/UBSan запусков: **1 112 063** ненулевых допустимых Unicode scalar values — round-trip и атомарный отказ на недостаточной ёмкости; отдельно malformed UTF-8/UTF-16.
- Unicode RW сверяется с независимым разбором FAT32/exFAT, mtools по SFN и `fsck.fat`/`fsck.exfat`. mtools 4.x в этой среде не разрешает surrogate-пары в длинных именах; это ограничение оракула, не основание менять emoji на `_` в ОС.
- Отдельно меняются реальные exFAT Up-case Table и NTFS `$UpCase`: поиск обязан следовать таблице тома, а не встроенной аппроксимации.
- На повреждённых Unicode-именах/таблицах проверяется отсутствие изменений исходного образа. NTFS остаётся byte-identical при попытках записи.
- Новые host/boot отчёты и логи — `build/unicode-*`. QEMU, ASan и fsck **не доказывают** устойчивость при пропадании питания или работу на каждом физическом устройстве.

## Что ещё НЕ поддержано

| Область | Точное ограничение |
| --- | --- |
| NTFS запись | **Нет**. Нельзя создавать/изменять/удалять NTFS-файлы. Полного `$LogFile` replay, транзакционного обновления индексов/MFT/bitmap и recovery ещё нет. Это главный блокер полной NTFS для 1.0. |
| NTFS чтение | Ограниченный MFT scan, не полноценный `$I30` B+tree; bootstrap `$MFT` с ATTRIBUTE_LIST не реализован. Не все размещения/служебные структуры доступны. |
| NTFS дополнительные функции | Нет DATA ADS API, LZNT1/compressed DATA, EFS, reparse traversal, enforcement ACL/security. Игнорирование named streams не означает их поддержку. |
| exFAT | Нет TexFAT и полноценного crash recovery. Запись больших файлов и большие тома сверх лимита аудита не добавлены. |
| FAT32 | Нет журналирования/crash consistency; возможны потери после отключения питания. OEM-only SFN без корректного LFN требует code-page драйвера. |
| Имена и пути | VFS путь/компонент максимум 255 **байт UTF-8**, имя на диске максимум 255 UTF-16 units. Не каждый допустимый 255-unit Unicode LFN помещается в VFS. Такие имена перечисляются меткой, без усечения в адресуемое имя; write preflight отказывает. |
| Unicode | Нет NFC/NFD normalization; `café` и `café` — разные имена. Нет полноценного grapheme/cell-width layout и встроенного Unicode-шрифта. Непарные surrogate отвергаются. |
| Размеры | HAL/LBA/размеры томов остаются 32-битными, текущий диск до 128 ГиБ, только 512-byte sectors; нет GPT/4Kn. Wide API чтения не расширяет HAL. |
| Legacy команды | TYPE/CRC32/COPY/запись не стали 64-битными. Для проверенного чтения >4 ГиБ используются STAT64/READAT/HEXAT и `fs_open64/fs_read64`. |
| Аудит записи | FAT32 ≤1 048 576 кластеров, exFAT ≤65 536; 32 768 записей аудита и глубина 16. Ограничения намеренные: неподдержанный том не становится RW. |
| Железо | Нет универсальной совместимости всех x86/x64 плат/USB-контроллеров. BIOS IDE и USB UHCI subset; UEFI опирается на прошивку. Нет доказательства на реальных машинах. |

**Запись — только на расходных копиях.** Успешный fsck после штатной операции не равен гарантии восстановления после обрыва питания. Сборка не публикуется; первым публичным выпуском остаётся запланированный стабильный Release 1.0 после завершения обязательных подсистем и отдельного решения автора.

## Портирование и редактирование образа

Драйверы ФС: `profiles/filesystems.mk`, `profiles/filesystems.registry.h`, `include/multios/fs_driver.h`. Общий Unicode-код: `lib/unicode.h`, `lib/util.c`; фиксированные case pairs — `lib/unicode_upcase.h`. Реальные таблицы NTFS/exFAT читает их backend.

Для добавления своего модуля реализуйте обязательные callbacks ABI 3, включая `read64` и `name_equal`; ошибка таблицы регистра должна возвращаться отрицательным кодом, а не выдавать «имена различаются». Проверьте registry/host и обе архитектурные сборки. C-модуль нужно **пересобирать**, замены текста `.c` на флешке недостаточно.

Один `.img` остаётся редактируемым. `tools/studio.py` пока намеренно принимает только ASCII-имена рабочей папки, чтобы не обещать Unicode round-trip через ограничения внешнего mtools. Не применяйте его к Unicode-томам: используйте копию и инструменты с подходящей поддержкой имён. Текущий образ поставляется с ASCII DATA и работает с этим редактором. Порядок `unpack/plan/apply` — в `START_HERE_RU.md`.

После изменения ядра обновляйте согласованный комплект BIOS kernel + raw mirror + UEFI binary через инструменты образа, не просто `KERNEL32.BIN` в произвольном редакторе. BIOS читает raw mirror. Исходники внутри `SOURCES/PORTING.ZIP` соответствуют поставляемому снимку; новая инструкция внутри ESP — `DOCS/UNICODE.MD`.
