# MultiOS 0.32-dev-exactnames / MultiPulti

Неопубликованная сборка разработки. Не стабильный Release 1.0. Запись FAT32, exFAT и NTFS остаётся экспериментальной; полная совместимость форматов не заявляется.

## Что исправлено

NTFS допускает существующие имена POSIX, отличающиеся только регистром. Раньше VFS мог открыть первый найденный файл `File.txt` вместо `file.txt`, а backend записи — изменить не тот inode. Для именованных потоков `Notes` и `notes` также выбирался первый вариант. Теперь VFS и NTFS-адаптер используют согласованный контракт:

1. Точное написание имеет приоритет.
2. Если точного имени нет, допускается единственное совпадение по таблице `$UpCase` тома.
3. Если вариантов несколько, возвращается UNSUP. Нельзя угадать, какой файл имелся в виду.
4. Ошибки перечисления не скрываются найденным ранее кандидатом.

Это действует для каждого компонента пути, включая каталог-родитель, и для потоков `$DATA`. Существующие `File.txt` и `file.txt` можно отдельно читать, заменять, копировать, переименовывать и удалять. `FILE.TXT` при наличии обоих отклоняется. Для единственного `Unique.TXT` путь `unique.txt` остаётся допустимым.

Перед изменением VFS проверяет неоднозначность источника и назначения. Для NTFS backend дополнительно выбирает точный inode по хранимому имени в рамках живого тома, не полагаясь на неоднозначную upstream ignore-case колляцию. Потоки используют exact-first lookup и ограниченный обход именованных DATA-атрибутов. Удаление и переименование получают каноническое имя существующей записи.

## Модульный контракт

В ABI 5 добавлена необязательная capability `MULTIOS_FS_EXACT_NAMES` (64). Размер структуры и callback ABI не менялись. Флаг объявляется расширенным NTFS-3G адаптером и означает exact-first + unique-folded fallback с теми же правилами внутри backend. Нельзя включать его для драйвера с другими правилами. FatFs/FAT32/exFAT и компактный read-only NTFS этот флаг не объявляют.

Изменение не создаёт интерфейс для новых коллизий регистра и не реализует Windows per-directory case-sensitive flags. `copyads` по-прежнему отказывает при неоднозначном наборе потоков с совпадением без учёта регистра: клонирование такого набора не поддерживается.

## Поставка и запуск

- `images/MultiOS-0.32-usb-fat32.img`, `-exfat.img`, `-ntfs.img` — три альтернативных raw-образа; выбирайте один.
- `MultiOS-0.32-FULL-SOURCES.zip` — код, upstream-компоненты, тесты, инструкции и лицензии.
- `bios-bundle/`, `uefi-bundle/` — согласованные BIOS i386 и UEFI x64 бинарники.
- `MultiOS-0.31-to-0.32.patch` — патч к FULL-SOURCES 0.31; для полного архива не нужен.
- `tools/` — настройщик образов и INI-профили; `reports/` и `TEST_FS_0_32_RU.md` — проверки.

Сначала сохраните данные флешки. Запишите выбранный `.img` побайтово, например Rufus DD. Прежняя разметка и данные в диапазоне образа будут уничтожены. Не используйте носитель с ценными данными.

BIOS/CSM требует EDD и поддержанный контроллер. UEFI x64 запускает `EFI/BOOT/BOOTX64.EFI`. Бинарник не подписан для Secure Boot; подпись и установка доверенных ключей не выполняются поставкой.

```text
ver
modules
fs
unlock YES
md DEMO
write DEMO/HELLO.TXT "Hello MultiOS"
append DEMO/HELLO.TXT "next line"
copyatomic DEMO/HELLO.TXT COPY.TXT
cmp DEMO/HELLO.TXT COPY.TXT
resize COPY.TXT 8193
writeat COPY.TXT 509 "PATCH"
sync
lock
```

Запись по умолчанию закрыта; `unlock YES` — только на расходной копии. `copyatomic` ограничен одной undo-транзакцией; `copy` использует staged-копирование порциями. Не извлекайте системную флешку во время работы.

## Настройка и сборка

Для ATA вместо фабричного BIOS USB BOT профиля:

```sh
python3 tools/customize.py images/MultiOS-0.32-usb-fat32.img --settings tools/ATA.INI --output MultiOS-ATA.img
```

Замена C-драйвера требует пересборки. Не подменяйте отдельно KERNEL32.BIN: raw-копия ядра, файлы, заголовок и CRC должны совпадать. Для изменения согласованного образа используйте installer и customize.

Из FULL-SOURCES, распакованного рядом с `images/` и `tools/`:

```sh
cd MultiOS
make bios-rw
make FS_PROFILE=profiles/filesystems-ntfs3g.mk uefi
python3 tools/build_bios_rw_image.py ../images/MultiOS-0.32-usb-fat32.img ../rebuilt-ata.img --efi build/BOOTX64.EFI
python3 tools/customize.py ../rebuilt-ata.img --settings ../tools/USB.INI --output ../rebuilt-usb.img
```

Нужны GCC/binutils, make, Python3, mtools. GNU-EFI runtime собирается из приложенного upstream-архива. Installer принимает подготовленный образ с чистым журналом, создаёт новую копию и не устанавливает ОС на произвольный физический диск. Обычный `make all` собирает другой компактный профиль.

## Ограничения

Private undo ограничен ёмкостью журнала конкретного образа. Поддерживается геометрия текущего HAL и 512-байтовые секторы. Грязные, гибернированные и неподдержанные тома не следует принудительно открывать для записи. Полный Windows ACL/EFS/reparse/$LogFile интерфейс, универсальное восстановление повреждённых томов и полная NTFS/Windows-совместимость отсутствуют. UEFI сохраняет Boot Services и использует firmware Block I/O; собственного xHCI нет. Проверки эмулятора не заменяют реальное оборудование и Windows chkdsk. Поддержка всех x86/x64 CPU и любых USB-устройств не гарантируется.

Исторические документы 0.31 и USB 0.28 сохранены; статус текущей сборки определяет этот документ. Основатели идеи — maslenko и krutoiperes11. Разработчик первого пререлиза — vm2 studios (t.me/v2vproj). Лицензии сторонних компонентов сохранены; объединённое ядро с NTFS-3G — GPL-2.0-or-later.
