# MultiOS 0.8-dev: экран и две кнопки

**MultiPulti · vm2 studios · t.me/v2vproj**

Неопубликованная сборка разработки. Первая публичная версия запланирована
только как **стабильный Release 1.0**. Названия старых ZIP и «выпусков» в
предыдущих материалах означают внутренние сборки, а не состоявшуюся публикацию.

## Управление без обычной клавиатуры

Нужны два логических события:

1. **NEXT / следующая**: перейти к следующей ячейке экранной клавиатуры.
2. **SELECT / выбрать**: нажать выделенную ячейку.

NEXT перебирает все 56 ячеек слева направо, сверху вниз; после последней снова
первая. Отдельных «вниз», «назад», долгого нажатия, одновременного нажатия или
третьей кнопки не требуется. Это простой полный перебор, не авто-сканирование
по таймеру. Не самый быстрый ввод, зато минимальный аппаратный контракт.

### Если кнопок три или больше

Третья функция — **PREVIOUS / предыдущая**: перебор тех же 56 ячеек в обратном
порядке, включая переход с первой на последнюю. На PC — **F5**. Не путать с
ячейкой Back: PREVIOUS меняет выделение, Back удаляет введённый символ.
При скрытой панели PREVIOUS также только открывает её.

Двухкнопочный BSP остаётся NEXT + SELECT: отсутствие PREVIOUS ничего не ломает.
В `ports/two-button.c.in` по умолчанию `MULTIOS_BOARD_BUTTON_COUNT=2`. При наличии
третьей физической кнопки установить `3` и вернуть её уровень как bit 4.
`multi_buttons_init(&state, 2)` не выдаёт PREVIOUS даже при лишнем bit 4;
`multi_buttons_init(&state, 3)` разрешает его. GPIO-helper обрабатывает и для
трёх кнопок только одиночные нажатия, с отпусканием всех кнопок для повтора.
Другие дополнительные кнопки можно отобразить отдельным драйвером.

На PC для проверки: **F6 = NEXT, F7 = SELECT** в BIOS PS/2 и UEFI input.
Это две используемые клавиши, а не требование иметь полную клавиатуру на новом
устройстве: GPIO-драйвер может отдавать те же два события напрямую.
Прежние стрелки + Enter и обычный ввод также сохранены.

- Ячейка **Enter** исполняет команду; физическая SELECT сама по себе не означает
  «исполнить команду»: на буквенной ячейке она вводит букву.
- **Space**, **Back**, **Shift**, **Tab**, **CtrlC** доступны в последней строке.
- **Shift** переключает раскладку, включая знаки пунктуации. Доступны все 95
  печатных ASCII-символов (в том числе обратная кавычка и тильда).
- **Hide** или **Esc** скрывает панель. При скрытой панели **любая из двух кнопок
  только открывает её**, не печатая символ. Следующее нажатие работает обычно.
  Положение и Shift сохраняются. Так же можно вернуться после команды `OSK OFF`.
- `OSK ON`, `OSK OFF`, `OSK TOGGLE` можно набрать через эту же панель.
- Для остановки наберите `EXIT`, для отключения питания — `POWEROFF`, если
  платформенный драйвер это поддерживает. BIOS-профиль пока умеет halt/reboot,
  а не физическое отключение питания. Включение выключенного устройства остаётся
  задачей его аппаратуры, не программы ОС.

Для примера: выбрать `v`, затем `e`, затем `r`, затем ячейку **Enter** — выполнится
`VER`. Это не DOS/Windows-совместимость программ: сходство касается консоли.

## Перенос «как DOOM»: что действительно заменять

Общие shell, exFAT, OSK и двухкнопочная логика не содержат ASM, GPIO, портов PC,
POSIX-вызовов или обращений к VGA. Между ними и платформой — `MultiHal`.
Начальный пример: **`ports/two-button.c.in`**.

Минимальная плата должна предоставить:

| Функция BSP | Назначение |
| --- | --- |
| `board_text_putc` | Печатать консоль на экране |
| `board_osk` | Нарисовать клавиши и выделение; раскладку брать из `multi_osk_label` |
| `board_buttons_wait_sample` | Получить устойчивые уровни двух кнопок |
| `board_read_sector`, `board_sector_count` | Читать 512-байтовые секторы exFAT-образа |
| `board_stop` | Корректно остановить выполнение на данной платформе |

Внешние устройства ввода — только две кнопки. Для ОС всё равно нужны CPU, RAM,
источник запуска и доступ к файловым данным. Диск/флешка не обязательны:
read-only exFAT можно встроить в ROM/прошивку и читать через блочный адаптер.
Запись файлов требует настоящих write/flush драйверов и writable-носителя;
шаблон намеренно read-only. Запись в ROM он не имитирует.

`board_osk` может рисовать на framebuffer, LCD или через прошивку: общий алгоритм
не требует 80x25. Но **готовые PC-рендереры сейчас рассчитаны на 80x25**; для малого
экрана нужно сделать свой renderer (например, показывать только выделенный символ
и его соседей). Готового универсального LCD/framebuffer-драйвера здесь нет.

**`include/multios/buttons.h`** превращает устойчивые уровни GPIO в события:
один event на нажатие; удержание не повторяет символ; для следующего события
нужно отпустить обе кнопки. Одновременное нажатие игнорируется до отпускания.
Электрическую полярность, подтяжки и debounce обеспечивает BSP. Нефильтрованный
контактный дребезг подавлять этим edge-helper нельзя — нужен фильтр на плате
или в её драйвере. Конкретный интервал зависит от кнопок/оборудования.

## Порядок создания порта

1. Выбрать ISA/ABI, компилятор, RAM/ROM map и способ запуска платы.
2. Реализовать startup, BSS/stack и linker script, не подменять их драйвером.
3. Скопировать `ports/two-button.c.in`, реализовать перечисленные `board_*`.
4. Сначала проверить экран и обе кнопки без доступа на запись.
5. Подключить read-only exFAT (внешний накопитель или ROM image), загрузить shell.
6. Проверить цикл NEXT, Shift, Back, Enter, Hide и восстановление обеими кнопками.
7. Проверить ошибки чтения. Только затем добавлять реальные write/flush.
8. Собрать свой бинарник для своей платформы и обновить образ выключенной системы.

На той же архитектуре с уже готовым BSP смена драйверов действительно может
сводиться к нескольким файлам/строкам профиля и пересборке. На другой ISA нужны
свои startup, ABI и linker script. **Один бинарник не запускается на всех CPU**,
а C-драйвер из чужой ОС нельзя просто скопировать. Динамической загрузки .sys/ELF
пока нет. BIOS/UEFI-образ не является готовой прошивкой для «голой» платы.

## Сборка и тесты

Linux/WSL, зависимости как в README_RU.md:

```bash
make all uefi multipulti
make test-two-buttons
make test-osk
python3 tests/cross_compile.py
python3 tools/mkunified.py --output build/My-New-Development.img
```

Последняя команда создаёт **новый** образ, а не затирает существующий. Для
обновления BIOS/UEFI бинарников в существующем едином образе после резервной
копии и полного выключения VM:

```bash
make update-unified
```

Это обновляет boot/kernel/EFI, но не синхронизирует автоматически исходники и
документацию внутри старого образа. Для текущего снимка исходников создайте новый
образ либо обновите `SOURCES/PORTING.ZIP` отдельно инструментом `imagectl.py`.

В архиве передаётся один raw-образ `build/MultiOS-MultiPulti.img` на 128 MiB,
исходники и инструкции. Редактирование — см. ONE_IMAGE_RU.md. Запись raw-образа
на флешку уничтожает её прежние данные. Изменения драйверов на C требуют
пересборки. Файловые записи в MultiOS всё ещё экспериментальны.
