# MultiOS 0.23-dev-writeguard — MultiPulti

vm2 studios | t.me/v2vproj. Неопубликованная разработка; НЕ стабильный Release 1.0.

## Назначение патча

Усиление сохранности записи FAT32, exFAT и NTFS в пределах существующего поддерживаемого оборудования. Расширение списка драйверов и полная реализация всех особенностей NTFS в этот патч не входят.

### Новые защиты общего транзакционного слоя

1. После записи каждой копии заголовка журнала выполняются flush и побайтное чтение-сравнение. Ошибка или несовпадение блокирует дальнейшую работу с записью.
2. Before-image и дескриптор сектора читаются и сравниваются после flush ДО публикации увеличенного счётчика журнала и ДО изменения защищаемого сектора.
3. Для каждого изменённого сектора в RAM хранится CRC32 последних запрошенных данных. После финального flush все уникальные сектора читаются и проверяются ДО первой CLEAN-копии — точки фиксации транзакции. Повторная запись сектора обновляет ожидаемый CRC.
4. При восстановлении, после flush, каждый восстановленный сектор побайтно сверяется с before-image. При несовпадении журнал не помечается CLEAN; следующая здоровая загрузка может повторить восстановление.
5. После открытия незавершённого журнала нельзя продолжить запись/commit без контекста текущей операции. Сначала обязательно восстановление. Проверяются допустимые переходы между двумя CRC-valid поколениями зеркал и чётность размера журнала.
6. При ошибках транзакция/ФС блокируются, кэши ФС больше не используются. Ошибка во время фиксации означает НЕИЗВЕСТНЫЙ результат: после новой загрузки допустим целиком старый либо целиком новый результат, а не обещание «ошибка означает, что ничего не произошло».

CRC32 — обнаружение случайной порчи, НЕ защита от злонамеренных изменений. Чтение после flush не доказывает запись на физический носитель, если контроллер/firmware лжёт о flush или возвращает собственный кэш. Данные не получают гарантий ECC, зеркалирования или криптографической аутентичности.

### BIOS ATA

Ожидание завершения команды требует снятого DRQ; зависание ограничено числом опросов. Проверяются IDENTIFY, ATAPI и заявленный размер логического сектора. 4Kn в этот VFS не допускается. Для RW требуется объявленная поддержка FLUSH CACHE либо валидное подтверждение отсутствующего/отключённого write cache. Неизвестные гарантии кэша переводят устройство в RO, а не дают фиктивную гарантию durability. RO-чтение остаётся доступным.

### Совместимость

Оба пути — BIOS i386 и x64 UEFI — используют усиленный общий журнал. Формат MPUNDO1 и MP22 не изменён: старые чистые образы можно обновлять штатным copy-only installer. Незавершённый журнал сначала восстанавливается. Дополнительные чтения и вычисление CRC замедляют запись; это сознательный приоритет сохранности над скоростью. В RAM дополнительно требуется около 16 КиБ таблицы CRC.

## Запуск

Архив содержит три raw-образа: NTFS, FAT32, exFAT, каждый с BIOS+UEFI. Это не ISO. Сначала запускайте КОПИЮ в QEMU/другой VM. BIOS: i386 ISA, минимум 32 МиБ RAM, IDE primary master, BIOS drive 80h/EDD и подходящая карта E820. Проверенные модели CPU в QEMU перечисляются в отчёте; это не гарантия всех x86. UEFI: x64 и firmware Block I/O, Boot Services сохраняются.

Запись raw-образа на отдельную флешку уничтожает её прежнее содержимое. Не выбирайте системный диск. USB-загрузка через UEFI зависит от firmware; нативный BIOS USB Mass Storage всё ещё отсутствует.

```
ver
fs
help
unlock YES
write TEST.TXT "MultiOS write test"
type TEST.TXT
lock
exit
```

RO по умолчанию и предупреждение EXPERIMENTAL намеренно сохранены. UNLOCK YES не означает сертифицированную стабильность. Не работайте с единственной копией важных данных. При ошибке записи не повторяйте команды вслепую: прекратите работу, сохраните образ и загрузите копию заново для восстановления.

## Пересборка и модификация

В исходниках с GCC/binutils, make, Python3, mtools и стандартными заголовками:

```
python3 tools/build_bios_ntfs.py
make FS_PROFILE=profiles/filesystems-ntfs3g.mk uefi
python3 tools/build_bios_rw_image.py /path/original.img /path/updated.img --efi build/BOOTX64.EFI
```

updated.img — НОВЫЙ файл. Installer не пишет на физические диски. Не изменяйте исходник одновременно со сборкой. В образе BIOS исполняет raw-копию ядра: замена только MULTIOS/KERNEL32.BIN не обновляет загрузку. Используйте installer, обновляющий raw-сектора, CRC, файлы ESP и SOURCES/PORTING.ZIP. Старый imagectl.py несовместим с MP22. Статические C-драйверы требуют пересборки; динамические .drv не добавлены. Исторический make all остаётся отдельным компактным профилем; расширенный BIOS RW строится указанным способом или make bios-rw-image с BIOS_RW_SOURCE/BIOS_RW_OUTPUT.

## Программные проверки

Тесты включают потерю кэша, частично сохранённые сектора, неупорядоченное частичное сохранение, завершившийся flush, аварии восстановления, тихо потерянную запись с успешным return, частичную запись 173 байта, порчу бита, ошибки чтения, бюджет/границы/поколения журнала и санитаризаторы. Дополнительно проверяются самостоятельные BIOS/UEFI загрузки и внешние утилиты ФС. Конкретные счётчики и результаты — в отчёте и логах, не заменяются обещанием сертификации.

## Оставшиеся ограничения

- Только 512-байтовые сектора, MBR, существующие пределы ёмкости; частный undo ограничен 4096 уникальными изменёнными секторами операции.
- Нативные BIOS AHCI/NVMe/USB Mass Storage отсутствуют. Нет 8086/286 и IA32 UEFI. Реальный 386 не проверен.
- NTFS не имеет полной Windows-семантики ACL/SID/reparse/EFS/BitLocker/$LogFile replay/chkdsk. Dirty/hibernated тома не разрешаются RW.
- BIOS время пока фиксированное fallback 2000-01-01 UTC. Это не актуальная дата файлов.
- Нет аппаратных проверок питания, износа, честности flush, misdirected writes и media faults. Модель не гарантирует защиту от записи контроллером в посторонний сектор.
- Дополнительное чтение/CRC выявляет не все возможные ошибки; резервные копии обязательны.

Полные соответствующие исходники NTFS-3G, FatFs и GNU-EFI, лицензии и NOTICE включены. Релиз 1.0 не объявляется этим патчем. Документ BIOS_RW_0_22_RU.md содержит подробности предыдущего загрузочного профиля; для новых защит и статуса приоритет имеет этот документ.
