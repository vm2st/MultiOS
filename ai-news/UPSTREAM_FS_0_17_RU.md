# MultiOS 0.17-dev-upstream — файловые системы и исправление UEFI

**MultiPulti · vm2 studios · t.me/v2vproj**

НЕОПУБЛИКОВАННАЯ ЭКСПЕРИМЕНТАЛЬНАЯ СБОРКА. Не Release 1.0. Все эксперименты — на копиях образов, не на единственном экземпляре данных. Полная стабильная совместимость всех ФС пока НЕ достигнута.

## Что действительно добавлено

| Изменение | Реализация | Ограничение / проверка |
|---|---|---|
| FAT32 RW | Операции изменения теперь выполняет ChaN FatFs R0.16 patch 2 | Отдельный профиль; чтение пока через собственный ограниченный драйвер |
| exFAT RW | Тот же FatFs: создание, перезапись, дописывание, копирование, удаление, каталоги, переименование | Не все возможности exFAT; проверяется собственным читателем перед/после записи |

| Большие файлы из небольших дописываний | Не переписывается весь старый файл при каждом append | Проверено 160 КиБ + хвост; размер одной транзакции ограничен |
| Unicode | UTF-8 API, LFN, CP866 короткие имена FAT32, non-BMP | Путь максимум 255 байт UTF-8; exFAT использует фактическую таблицу $UpCase тома |
| NTFS RW в x64 UEFI | Настоящая библиотека NTFS-3G 2022.10.3; собственный блочный backend, allocator и C runtime | Без Linux/FUSE/другой ОС во время работы; BIOS NTFS остаётся RO |
| NTFS обычные файлы | Create/replace/append/copy/rename/delete; resident → nonresident | Не универсальная поддержка NTFS |
| NTFS каталоги | mkdir/rmdir, рост MFT и индексов | Проверено 120 длинных имён; непустой каталог не удаляется |
| Предохранители NTFS | Отказ для dirty/hibernated томов, системных метафайлов и неподдерживаемых объектов | Автоматического ремонта $LogFile и снятия гибернации НЕТ |
| Защита записи | Частный undo-журнал под общим VFS для всех трёх ФС | Не собственный журнал NTFS $LogFile, не обещание защиты от любого аппаратного сбоя |
| Исправление EFI | KEEP(.reloc), включение .bss.* в экспортируемый образ, запрет неразрешённых символов | OVMF раньше мог сообщать Not Found вместо загрузки; итоговые образы тестируются отдельно |
| Исправления порта | Владение strdup/heap, закрытие inode/parent, отмена ошибочных NTFS операций, выравнивание UEFI heap | Ошибки найдены тестами ASan/UBSan и fault injection |
| i386 арифметика | Собственные unsigned 64-bit division/remainder без libgcc | 100056 пар сравнены с native x64 arithmetic |

## Архитектура и модули

- `profiles/filesystems.mk` — прежняя реализация; не стала автоматически новой.
- `profiles/filesystems-fatfs.mk` — FAT32/exFAT FatFs + undo; собирается для BIOS и UEFI.
- `profiles/filesystems-ntfs3g.mk` — дополнительно NTFS-3G; **только x64 UEFI и host-тестовый стенд**.
- `lib/fatfs_adapter.c`, `lib/ntfs3g_adapter.c` — мосты между VFS, настоящими upstream-движками и HAL.
- `ports/ntfs3g/` — изолированный freestanding-порт. До 32 МиБ данных heap на операцию; служебные заголовки allocator и накладные расходы прошивки сверх этого.
- `vendor/` — исходники upstream, версии, контрольные суммы, лицензии. Никакой загрузки библиотек из Интернета во время сборки не требуется.
- `platform/uefi/sections.ld` — EFI linker script с сохранением PE relocations.

Это **статическая модульность**: настройки выбирают уже собранные драйверы. Изменение C-драйвера требует пересборки. ABI для произвольных загружаемых `.drv` и безопасная горячая замена ещё не реализованы. Для нового устройства потребуются HAL/BSP и реально работающие драйверы, а не просто переименование файлов.

UEFI-вариант работает самостоятельно как EFI-приложение и **сохраняет Boot Services**. Диски и USB-клавиатура здесь обслуживаются прошивкой. Это не завершённое x64-ядро после ExitBootServices и не нативный универсальный USB storage stack. BIOS-вариант — отдельное собственное i386-ядро; его текущий дисковый путь — primary-master IDE. Поддержка всех x86/x64 и загрузка на любом устройстве не гарантируются.

## Образы и простой запуск

В комплекте три **альтернативных** самостоятельных `.img`:

- `MultiOS-0.17-dev-upstream-fat32.img` — рекомендован для первого знакомства и простого внешнего редактирования файлов.
- `MultiOS-0.17-dev-upstream-exfat.img` — exFAT data.
- `MultiOS-0.17-dev-upstream-ntfs.img` — NTFS data, экспериментальная запись только UEFI.

Каждый образ содержит BIOS boot sectors, FAT32 ESP с `/EFI/BOOT/BOOTX64.EFI`, выбранный раздел данных и приватный undo-раздел. Это не три ФС внутри одного data-раздела. Размер около 129 МиБ.

1. Сохраните оригинал, работайте с копией. В QEMU подключите именно **весь образ**, а не вырезанный data-раздел. Для VirtualBox сначала преобразуйте копию raw-образа: `VBoxManage convertfromraw MultiOS-0.17-dev-upstream-fat32.img MultiOS.vdi --format VDI`, затем подключите VDI как диск и включите EFI x64. Для UEFI x64 используйте 64-битную прошивку, Secure Boot отключён: бинарник не подписан доверенным ключом.
2. В меню UEFI выбирайте накопитель с этим образом. Если он не загрузился: Boot From File → FAT32-раздел MULTIOSBOOT → `EFI/BOOT/BOOTX64.EFI`. Для 32-битного UEFI загрузчика BOOTIA32.EFI пока нет.
3. QEMU/OVMF: `python3 tools/run_upstream.py images/MultiOS-0.17-dev-upstream-fat32.img`. Python-скрипт запускается на компьютере разработчика; гостевой Linux/Windows не нужен.
4. В консоли: `HELP`, `VER`, `FS`, `DIR`. По умолчанию RO. Для записи на копии:

```text
UNLOCK YES
MD TEST
WRITE TEST/a.txt "Hello MultiOS"
APPEND TEST/a.txt "second line"
COPY TEST/a.txt TEST/b.txt
CMP TEST/a.txt TEST/b.txt
REN TEST/b.txt final.txt
TYPE TEST/final.txt
DEL TEST/final.txt
DEL TEST/a.txt
RD TEST
LOCK
POWEROFF
```

Полная клавиатура работает через доступный драйвер: UEFI keyboard protocol/firmware USB либо BIOS-профиль. Экранная клавиатура — F2/Ctrl+O; две кнопки NEXT/SELECT, PREVIOUS только при наличии дополнительной кнопки. Экранная клавиатура сама по себе не создаёт драйвер GPIO/тачскрина.

## Редактирование одного образа

Выключите VM, сделайте резервную копию. На FAT32 ESP находятся `MULTIOS/BOOT.CFG`, `MULTIOS/KERNEL32.BIN`, `EFI/BOOT/BOOTX64.EFI`, `SOURCES/PORTING.ZIP`, документация. Настройки можно менять без компиляции в пределах уже встроенных модулей.

Исходники — в архиве проекта и в `SOURCES/PORTING.ZIP` каждого готового образа. После изменения драйвера пересоберите и **создайте новый образ**. Не заменяйте один KERNEL32.BIN обычным редактором: BIOS загружает его raw-зеркало. Для согласованной установки пары BIOS/EFI используйте `tools/imagectl.py install --help`.

`tools/studio.py` — прежний ограниченный FAT32-редактор, не универсальный NTFS/exFAT редактор и не инструмент безопасного изменения служебных разделов. После внешнего редактирования data-раздела следует проверить ФС; не меняйте геометрию приватного undo-раздела и не редактируйте образ с незавершённой транзакцией.

## Сборка из исходников на Linux / WSL

Нужны GCC (включая `-m32` freestanding), binutils, make, Python 3, GNU-EFI с headers/crt/libs, dosfstools, mtools, exfatprogs, ntfs-3g/ntfsprogs. Для тестов: QEMU x86_64, OVMF; ASan/UBSan runtime для sanitizer-сборок. На Fedora/Amazon Linux названия пакетов могут отличаться. Путь к GNU-EFI задаётся `EFIINC`, `EFILIB`, `EFICRT` (см. Makefile).

```sh
make upstream-image UPSTREAM_DATA_FS=fat32 UPSTREAM_OUTPUT=build/my-new-fat32.img
make upstream-image UPSTREAM_DATA_FS=exfat UPSTREAM_OUTPUT=build/my-new-exfat.img
make upstream-image UPSTREAM_DATA_FS=ntfs UPSTREAM_OUTPUT=build/my-new-ntfs.img
```

Команда сначала собирает небольшой BIOS FatFs-вариант, затем x64 UEFI с NTFS-3G; **не используйте NTFS-профиль для i386 kernel**. Существующие файлы назначения не перезаписываются. Создание образа само по себе не подтверждает загрузку на физическом компьютере.

## Границы стабильности — важно

- Undo хранит **128 разных изменённых секторов по 512 байт на одну операцию**, включая данные и метаданные. Это не лимит размера файла, но крупная/фрагментированная операция может не поместиться и будет отменена. Не дробим операцию неявно на частично успешные шаги.
- Успешный flush должен действительно сохранять данные. Ошибки контроллера, ложный flush, torn writes вне принятой модели, отказ самого носителя не покрываются обещанием полной сохранности.
- GPT, 4Kn, RAID, BitLocker, произвольные типы разделов и вся аппаратная периферия не поддерживаются этим путём. HAL: 512-байтные секторы, текущая адресация до 128 ГиБ; ряд собственных читателей имеет меньшие структурные лимиты.
- NTFS: сжатые/EFS/reparse файлы для мутаций отвергаются; команд для ADS, ACL, hardlinks, sparse controls и полного Windows security model нет. Не заявляется полноценный chkdsk, самовосстановление $LogFile, совместимость всех версий NTFS/Windows и серверных томов.
- FatFs внедрён в **операции записи**, не заменил целиком собственный стек чтения. Поэтому ограничения старого парсера каталогов, числа extent/run и поддерживаемой геометрии остаются значимыми.
- Нет сертификации на физических устройствах, полной BIOS-runtime проверки в этой среде, fuzzing всей поверхности NTFS и реальных аппаратных power-cut испытаний.

При ошибке записи VFS может блокировать дальнейшую работу с томом до перемонтирования/перезапуска. Это защитный отказ, не разрешение продолжать запись. Не форматируйте и не удаляйте undo-раздел, пока возможна незавершённая транзакция.

## Проверки и воспроизведение

`reports/upstream-fs/` содержит отчёты, а `tests/` — исполняемые сценарии. Реальные C-проверки считают отдельные assertions; это **не миллионы разных сценариев**.

- FAT32: обычная и ASan/UBSan матрицы, по 1336 точек сбоя/аварийного завершения и 1336 возвращаемых ошибок I/O; 81 прерывание восстановления.
- exFAT: по 1164/1164 и 65 прерываний восстановления в каждом из двух запусков.
- NTFS-3G: обычный и полностью инструментированный ASan/UBSan порт: по 3520/3520 и 129 прерываний восстановления.
- FAT32/exFAT: seeded-модель из 96 операций, 12 внешних fsck-контрольных точек на ФС; отдельно 120 длинных имён, Unicode и 160 КиБ пошагового append.
- NTFS: внешнее чтение полных данных через ntfscat, перечисление ntfsls, базовый `ntfsfix -n` (**не замена Windows chkdsk**), отказ гибернированного тома без изменения образа.
- Финальные EFI-образы проверяются в OVMF/QEMU с USB storage/keyboard, затем fsck либо независимое ntfscat-чтение. Время одного запуска эмулятора не является гарантией секунд на любом ПК.

```sh
make test-fatfs
# Сборка NTFS host harness + тест роста/внешнего чтения:
make FS_PROFILE=profiles/filesystems-ntfs3g.mk build/multios-host build/upstream-growth build/storage-tx-test
python3 tests/upstream_ntfs.py
# Проверка готового NTFS-образа:
MULTIOS_UPSTREAM_IMAGE=/path/to/ntfs.img python3 tests/upstream_ntfs_boot.py
```

Для байтового сравнения NTFS fault injection требуется `MULTIOS_NTFS_TEST_TIME=1`; в production время берётся из host clock либо UEFI RTC. `storage_tx_test.c` ожидает отдельный подготовленный тестовый том с `old.txt` и каталогом `empty`, а не образ с ценными данными. Санитайзеры должны инструментировать и библиотеку NTFS-3G, не только оболочку; смена CC-флагов требует удаления `build/ntfs3g-host/` и пересборки host binaries.
