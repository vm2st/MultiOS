# MultiOS 0.20-dev-fileio — системная запись и изменение размера

MultiPulti · vm2 studios · t.me/v2vproj. **Неопубликованная development-сборка, НЕ стабильный Release 1.0.**

## Реализовано после 0.19

1. **Общий 64-битный VFS API** `fs_write64(path, offset, data, count)` и `fs_resize64(path, size)` для FAT32/exFAT (FatFs) и NTFS (NTFS-3G). Это реальная работа драйверов через блочный HAL и приватный undo-журнал, не эмуляция файлов Linux/FUSE в гостевой системе.
2. **WRITEAT** меняет точные байты внутри существующего файла. Не создаёт файл, не дописывает перевод строки, не расширяет его неявно. Для расширения сначала RESIZE. Смещения проверяются вычитанием без переполнения.
3. **RESIZE** расширяет существующий файл с логическими нулями, обрезает его или делает пустым. После обрезания и повторного расширения старые данные не должны появляться. Для NTFS разреженные области могут оставаться физически не выделенными; это нормальная семантика файловой системы.
4. **Исправлена проблема конфиденциальности exFAT ValidDataLength.** FatFs при синхронизации записывает ValidDataLength=FileSize. Теперь перед дописыванием/записью по смещению материализуется нулями весь неинициализированный хвост; при изменении размера — сохраняемая/новая область. Иначе старые байты носителя могли стать содержимым файла. Если материализация не помещается в транзакцию, операция откатывается, том требует повторного mount/reboot. Не снимаем защиту ради успешного ответа.
5. При COPYATOMIC неинициализированный хвост источника exFAT маскируется нулями; нельзя копировать физические старые данные. Обычный staged COPY использует VFS read64 и сохраняет защиту нулевых областей.
6. **Аудит записи больших exFAT-файлов** теперь считает кластеры 64-битно. В x64 UEFI/host upstream-профиле workspace увеличен до 1 048 576 кластеров. BIOS сохраняет прежний небольшой workspace 65 536 кластеров, без расхода дефицитной низкой памяти. Каталоги с неподдерживаемыми большими метаданными всё ещё отклоняются. Большой размер не равен полной поддержке любой геометрии exFAT.
7. **Контракт модулей ФС ABI 4.** Добавлен optional capability `MULTIOS_FS_RANDOM_IO` с парой callbacks write_at/resize. Его можно объявлять только вместе с WRITE и обоими callbacks. Старые ABI-драйверы намеренно отклоняются, а не интерпретируются по неверной структуре. Все включённые дескрипторы обновлены. Исторические legacy-драйверы не получают ложных новых возможностей.
8. Исправлена особенность NTFS-3G: truncate сжатого nonresident-файла мог вернуть успех, но расширить его лишь до границы блока сжатия. Точное расширение теперь выполняется нулевыми записями; размер проверяется после pclose. Отдельный регрессионный тест проверяет LZNT1 write-at/grow/shrink/regrow.
9. Счётчик свободных KiB в DF переведён на 64-битное вычисление для согласованности с wide API. При нынешнем HAL-лимите 128 ГиБ прежний KiB-счётчик сам по себе не был блокером.
10. Старые 64-битные views инвалидируются до dispatch изменяющей операции, включая неуспешную. Отказ до dispatch и настоящие no-op не инвалидируют корректный view. Добавлены проверки эпох, ABI и callback/capability-контракта.

## Пример работы

```text
HELP
UNLOCK YES
WRITE /TEST.TXT "Hello MultiOS"
STAT /TEST.TXT
RESIZE /TEST.TXT 64
WRITEAT /TEST.TXT 6 "MultiPulti"
CRC32 /TEST.TXT
RESIZE /TEST.TXT 5
TYPE /TEST.TXT
COPY /TEST.TXT /COPY.TXT
CMP /TEST.TXT /COPY.TXT
LOCK
POWEROFF
```

WRITEAT требует, чтобы текст целиком помещался в текущий размер. RESIZE 64 сначала создаёт нужное место. Команда WRITE, в отличие от WRITEAT, имеет прежнюю текстовую семантику оболочки. Нули удобнее проверять CRC32/HEX, а не TYPE. Пробелы в текстах/путях заключайте в кавычки. Числа — беззнаковые; соблюдайте ограничения тома. FAT32 не может иметь файл больше 4 ГиБ−1 байт.

### Атомарность и ошибки

WRITEAT/RESIZE — **одна ограниченная undo-транзакция**. Журнал готовых образов защищает до 4096 разных изменённых секторов (около 2 МиБ данных, меньше при дополнительных метаданных), не произвольно большой файл за одну операцию. Размер существующего файла может быть больше этого лимита, если конкретная операция укладывается в журнал. Большая физическая инициализация/очистка может получить NOSPACE даже при свободном диске.

При любой ошибке мутации: не продолжайте через старые handles, не обходите RO. Перезагрузите/переподключите образ; recovery выполняется до записи. Уже committed операция может оказаться завершённой, даже если последующее подтверждение flush потерялось. После восстановления допустим целый старый или целый новый результат, но не частично опубликованное содержимое. Тесты моделируют выбранные отказы, не все свойства реальных контроллеров/питания.

COPY остаётся проверяемым staged-копированием по 8192 байт с COPYPAUSE/COPYRESUME. Это не атомарность всей многогигабайтной копии и не клонирование ACL/ADS/hardlinks. Подробности предыдущего патча — FILESYSTEMS_0_19_RU.md.

## Запуск и установка

В `images/` три альтернативных raw-образа:

- `MultiOS-0.20-dev-fileio-fat32.img`
- `MultiOS-0.20-dev-fileio-exfat.img`
- `MultiOS-0.20-dev-fileio-ntfs.img`

Каждый содержит BIOS bootstrap/kernel, FAT32 ESP, выбранный data-раздел и отдельный undo-раздел. Это не три ФС в одном разделе. Начинайте с КОПИИ FAT32-образа в x64 UEFI VM, Secure Boot отключён (EFI не подписан доверенным ключом).

Из `source/MultiOS`:

```sh
python3 tools/run_upstream.py ../../images/MultiOS-0.20-dev-fileio-fat32.img
```

Launcher использует временную копию и не сохраняет изменения после выхода. Для постоянной работы подключите отдельную сохраняемую копию в VM. Для VirtualBox:

```sh
VBoxManage convertfromraw MultiOS-0.20-dev-fileio-fat32.img MultiOS.vdi --format VDI
```

Не копируйте raw-образ на флешку обычным перетаскиванием файла: для загрузки нужна запись образа. Это уничтожает существующее содержимое выбранного носителя. В этом патче физические носители не проверены; безопаснее VM. Нет нового автоматического установщика/форматирования физических дисков.

Внутри образа доступны `MULTIOS/BOOT.CFG`, `DOCS/FS20.MD`, `SOURCES/PORTING.ZIP`. Редактируйте только выключенный образ. C-модули статически компилируются, это не горячая загрузка .dll. После изменения драйверов нужна пересборка. BIOS читает также raw-зеркало ядра: не заменяйте только KERNEL32.BIN общим редактором — применяйте imagectl install или создайте новый образ.

## Сборка и тесты

Linux/WSL: GCC/binutils/make/Python, dosfstools/mtools/exfatprogs/ntfs-3g; для загрузки QEMU+OVMF. GNU-EFI по умолчанию собирается из включённого source archive с baseline x86-64. FatFs и NTFS-3G включены исходниками, их лицензии сохранены. NTFS-вариант EFI содержит GPL-компонент: при распространении обязательны соответствующие исходники и уведомления.

```sh
make upstream-image UPSTREAM_DATA_FS=fat32 UPSTREAM_OUTPUT=build/new-fat32.img
make upstream-image UPSTREAM_DATA_FS=exfat UPSTREAM_OUTPUT=build/new-exfat.img
make upstream-image UPSTREAM_DATA_FS=ntfs UPSTREAM_OUTPUT=build/new-ntfs.img
make FS_PROFILE=profiles/filesystems-ntfs3g.mk build/fs-random-probe build/fs-random-probe-sanitize
python3 tests/random_io.py
python3 tests/wide_random_io.py
MULTIOS_RANDOM_PROBE="$PWD/build/fs-random-probe-sanitize" python3 tests/random_io.py
make test-file64-epoch test-fs-registry check-core
```

В средах, где sanitizer runtime находится только в каталоге компилятора, задайте соответствующий LD_LIBRARY_PATH; не отключайте sanitizer ради успешного теста. Все тестовые образы одноразовые, physical devices не используются. wide_random_io временно требует около 9 ГиБ свободного места (разреженный том и защищённая копия).

## Что ещё НЕ завершено — блокеры Release 1.0

- **Не полная совместимость NTFS:** нет обещания поддержки BitLocker/EFS, произвольных reparse points, Windows ACL/access-check policy, интерфейсов всех ADS/атрибутов, полноценного $LogFile replay и chkdsk. Приватный undo — НЕ замена NTFS-журналу на произвольном ранее повреждённом/грязном Windows-томе. Опасные состояния должны отклоняться, а не насильно открываться RW.
- NTFS-3G RW интегрирован в UEFI/host. **BIOS NTFS остаётся RO**; нет полного NTFS-3G в BIOS low-memory kernel.
- FAT32/exFAT RW реализованы для поддерживаемого подмножества, а не сертифицированы на всех дисках. Ограничения аудита: FAT32 до 1 048 576 кластеров; exFAT UEFI/host upstream до 1 048 576, BIOS до 65 536; ограниченная глубина/число записей каталогов. Нет обхода ограничений ради открытия записи.
- Блочный путь по-прежнему 512 байт/сектор, MBR, до 128 ГиБ; нет полного GPT/4Kn/extended partitions. Размер кластера exFAT ограничен текущим парсером.
- UEFI использует firmware Boot Services/Block I/O и firmware input; это не новый нативный x64 kernel после ExitBootServices. Нет универсального native USB/storage/NVMe/AHCI стека. BIOS target — i386/IDE primary master; runtime BIOS в этой среде не проверен.
- Нет доказанной работы «на каждом x86/x64», реального power-cut тестирования, полной crash-consistency сертификации и массового hardware QA.

**Итог:** закрыты конкретные недостающие операции и опасный случай exFAT, но объявлять всю работу по всем ФС окончательно законченной или выпускать стабильную 1.0 сейчас технически неверно.
