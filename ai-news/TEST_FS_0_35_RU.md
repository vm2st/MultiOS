# MultiOS 0.35 — результаты проверки

Статус: **полный локальный software gate PASS**. Неопубликованная разработка,
не Release 1.0. Реальное оборудование не проверялось.

## Новые регрессии

- До исправления воспроизведён успешный commit после проигнорированного NOSPACE.
  После исправления — отказ commit, полный откат, новая транзакция и восстановление
  после повторного открытия. Проверены также неверный диапазон и NULL-буфер.
- На реальных образах FAT32/exFAT/NTFS проверены три ошибочных положительных
  статуса операции: все откатываются. Заполнен весь undo-бюджет в 4096 секторов,
  следующая запись отклонена; ложный успех модуля не фиксирует частичный результат.
  Все исходные защищённые секторы сверены побайтно. Затем проверены повторное
  монтирование, новая транзакция и обычная запись файла.
- Эти интеграционные тесты повторены с ASan/UBSan. Для данного сценария выбран
  штатный бюджет 4096; тесты с малым бюджетом не считаются доказательством,
  что обычное создание NTFS-файла обязано помещаться в этот бюджет.
- Контрактные тесты модулей: положительный статус mount, подмена геометрии,
  семь изменяющих callbacks, read32/read64/free, неверное значение перечисления,
  непродвигающийся курсор, запрет обращения к размонтированному тому.
- HAL: writable=-1 и writable=2 отвергаются.

На настоящих файловых образах повторены **644 выбранных комбинации отказов**:
226 для random I/O, 198 для staged copy и 220 для NTFS streams/hardlinks.
Это выбранные границы сырой записи × два режима отказа, а не исчерпывающий
перебор всех возможных обрывов и не 644 новых функции. Повторение тех же случаев
под санитайзерами не удваивает число уникальных сценариев.

Базовые внешние проверки: fsck.fat, fsck.exfat, ntfsfix и чтение содержимого
независимыми утилитами там, где они доступны. ntfsfix не заменяет Windows chkdsk.

## Проверка готовых образов

Все три образа FAT32/exFAT/NTFS загрузились в QEMU Q35 + OVMF через UEFI.
Проверены версия 0.35, пять отказов опасным именам, запись, копирование,
resize, write-at, сравнение файлов, завершение работы и сохранённые байты
после выключения. Проверки выполнены на временных копиях; исходные поставляемые
образы не загрязнены тестовыми файлами.

USB-диск и клавиатура предоставлены прошивкой через эмулированный xHCI.
Это **не** подтверждение нативного xHCI MultiOS. Установленная здесь сборка QEMU
не имеет требуемого PC/IDE-профиля для существующего BIOS-теста: BIOS отмечен
только как собранный, не как проверенный загрузкой.

## Воспроизведение и поставка

```sh
python3 tools/check_filesystems.py
make -j4 test-usb-enum test-usb-bot test-usb-bulk-hosts test-fatfs-bridge test-unlock-contract
make -j4 FS_PROFILE=profiles/filesystems-ntfs3g.mk build/fs-read-probe
MULTIOS_BOOT_MODES=uefi python3 tests/fs_path_boot.py PATH_TO_IMAGES
```

Для последнего теста задайте OVMF_CODE и OVMF_VARS, если файлы прошивки находятся
не в путях по умолчанию. Нужны QEMU и OVMF. GitHub workflow добавлен, но удалённый
запуск Actions в пользовательском репозитории этой проверкой не подтверждён.

В полном комплекте приложены текстовые логи и машиночитаемый results.json.
Пути рабочей среды в поставляемых отчётах заменены нейтральными обозначениями.
