# MultiOS / MultiPulti — единый редактируемый образ

> Текущий снимок: **0.11-dev, не опубликован**. Первая публичная версия — только
> стабильный **Release 1.0**. См. RELEASE_POLICY_RU.md и TWO_BUTTONS_RU.md.

vm2 studios — t.me/v2vproj

MultiPulti — имя собственного лёгкого C-ядра BIOS-ветки и общего C-core проекта.
MultiOS — вся система. UEFI-ветка пока отдельное firmware-hosted приложение,
а не нативное x64-ядро после ExitBootServices. Совместимость с каждым x86/x64
процессором и каждым устройством не обещается: см. ниже.

## Устройство образа

`build/MultiOS-MultiPulti.img` — один raw-образ на 128 MiB:

1. MBR и 32-битное MultiPulti в зарезервированных секторах 1–240.
2. FAT32 boot-раздел 64 MiB (LBA 2048): EFI-loader, конфигурация, зеркальная
   копия KERNEL32.BIN, инструкции, инструмент редактирования и исходники.
3. exFAT data-раздел 63 MiB (LBA 133120), **один и тот же** для BIOS и UEFI.

В едином образе **нет DATA.IMG**: обе ветки используют настоящий второй раздел.
Исходный USB file-backed вариант сохранён для совместимости в `make usb`.
Здесь образ содержит и файлы для работы, и комплект для портирования:
`SOURCES/PORTING.ZIP`. Это снимок исходников на момент создания, не автосинхронизация
с последующими правками; после их изменения архив обновляется отдельно.

## Создать / пересобрать

Linux/WSL: GCC, binutils с i386 target, Python 3, GNU-EFI, dosfstools и mtools.
Точные команды установки и пути GNU-EFI — в USB_RU.md / README_RU.md.

```bash
make unified
```

Если образ уже существует, эта команда его не перезаписывает, чтобы не уничтожить
данные. Новый чистый образ можно создать под новым именем:

```bash
python3 tools/mkunified.py --output build/new-multipulti.img
```

## Поменял → сохранил → загрузил

Работайте **только с выключенной копией**, не с образом запущенной VM/подключённым
для записи разделом. Сначала сделайте полную резервную копию `.img`. imagectl
работает лишь с обычными файлами данного формата, не с `/dev/...` и не с флешками.
Нужны Python 3 + mtools + fsck.fat (dosfstools) (в Windows — через WSL). Изменение делается во временной
копии в той же папке, затем атомарно заменяется исходный файл; нужно ещё 128 MiB
свободного места. Это защита host-редактирования, не журналирование exFAT.

Просмотреть содержимое и авторство:

```bash
python3 tools/imagectl.py info build/MultiOS-MultiPulti.img
```

Выбрать уже встроенный драйвер, сохранить тот же образ и запустить снова:

```bash
python3 tools/imagectl.py set build/MultiOS-MultiPulti.img block uefi-boot-disk-ro
python3 tools/imagectl.py set build/MultiOS-MultiPulti.img osk off
```

`uefi-boot-disk-ro` запрещает запись даже после UNLOCK. Вернуть capability:

```bash
python3 tools/imagectl.py set build/MultiOS-MultiPulti.img block uefi-boot-disk
```

ФС всё равно начинает в RO, экспериментальная запись требует `UNLOCK YES`.
Простой вывод без панели: `output uefi-plain` вместе с `osk off`.
Конфиг действует **только в UEFI**. BIOS-профиль по-прежнему компилируется.
Выбор `uefi-file` не подходит этому образу без отдельно добавленного DATA.IMG.

### Изменить исходник драйвера

Исходники находятся в дереве проекта и в архиве внутри образа:

```bash
python3 tools/imagectl.py get build/MultiOS-MultiPulti.img SOURCES/PORTING.ZIP porting.zip
```

Распакуйте, измените `drivers/.../*.c`, профиль и реестр, выполните сборку.
**Копирование `.c` не превращает его в драйвер**: пока это статические C-модули,
а не загрузчик ELF/DLL/.sys. Исполняемый комплект нужно обновить после компиляции:

```bash
make all uefi
python3 tools/imagectl.py install build/MultiOS-MultiPulti.img \
  --kernel build/kernel.bin --efi build/BOOTX64.EFI
```

Или коротко из исходного дерева:

```bash
make update-unified
```

Данные exFAT и BOOT.CFG при этой операции сохраняются. Если новый профиль меняет
ID модулей, отдельно исправьте BOOT.CFG. Не устанавливайте minimal/file-backed
профиль, не содержащий `uefi-boot-disk`, в unified-образ с прежним конфигом.

Заменить одну готовую сборку:

```bash
python3 tools/imagectl.py put build/MultiOS-MultiPulti.img EFI/BOOT/BOOTX64.EFI build/BOOTX64.EFI
python3 tools/imagectl.py put build/MultiOS-MultiPulti.img MULTIOS/KERNEL32.BIN build/kernel.bin
```

Для KERNEL32.BIN инструмент обновляет **и файл, и реальные BIOS boot-сектора**.
Обычный файловый редактор образов этого не делает — менять только зеркальный
KERNEL32.BIN в нём недостаточно. Обновление MBR-кода данным инструментом не
предусмотрено. Загруженный драйвер нельзя заменить на лету.

## Запуск / флешка

`./run-unified.sh bios` или `./run-unified.sh uefi` запускает готовый образ через
QEMU, предварительно создав сохраняемую рабочую копию `build/unified-work.img`.
После обновления исходного образа уже существующая рабочая копия не обновится;
сохраните из неё нужные данные и создайте новую копию вручную либо используйте
`MULTIOS_IMAGE=build/MultiOS-MultiPulti.img ./run-unified.sh uefi` для прямой работы
с указанным выключенным образом (он будет изменяться гостем).

Для флешки это **запись всего raw-образа**, а не копирование `.img` как файла.
Запись сотрёт таблицу разделов и данные выбранного носителя; используйте только
пустую ненужную флешку, проверьте устройство и резервную копию. Проект сам не
пишет на физические диски. Копирование одних FAT-файлов на произвольную флешку
не создаст требуемый второй раздел для `uefi-boot-disk`.

## Честная совместимость

- BIOS: собственный freestanding kernel, C11 + небольшой startup assembler,
  набор инструкций i386, BIOS EDD, VGA, IDE primary master, сектор 512 байт.
- BIOS ATA проверяет случайный MBR disk ID, сохранённый загрузчиком в RAM,
  и прекращает подключение при несовпадении с primary master. Это защита от
  случайного выбора другого внутреннего диска, не средство аутентификации.
  Клоны с одинаковым ID этим способом не различаются. Универсальная BIOS USB-
  загрузка всё равно не поддерживается; используйте UEFI или IDE-образ QEMU.
- На подходящем x86-64 с BIOS/CSM работает то же 32-битное ядро, не native64.
- x64 UEFI: отдельное приложение, Boot Services активны; контроллером управляет
  прошивка, новый адаптер использует UEFI Block I/O, не собственный USB/NVMe.
  Диск выбирается по **точному родительскому Device Path загрузочного раздела**,
  не как первый найденный накопитель. Неоднозначность/несовместимость — ошибка.
- UEFI IA32, native64 после ExitBootServices, все AMD/Intel/VIA/SoC,
  8086/286, произвольные SATA/AHCI/NVMe/USB в BIOS, Secure Boot — не заявлены.
- Собственные xHCI/HID/AHCI/NVMe, scheduler, VMM и программы EXE/ELF не появились
  от переименования ядра. Поддержка процессора ≠ поддержка платы/контроллеров.
- Нет проверки на физическом оборудовании; критерий текущей готовности — QEMU.

## Обновление CPU-совместимости в 0.6

Подробная политика и проверенная матрица — `CPU_COMPAT_RU.md`. Команда `CPU`
не требует CPUID для BIOS-ветки. Общий минимум по-прежнему i386, 16-битной
ветки 8086/286 нет. Убран обязательный port 0x92: нынешние адреса ниже 1 MiB.

Для полного обновления изменённого загрузчика используйте `make update-unified`
или добавьте `--boot build/boot.bin` к ручной команде install выше. Этот параметр
обновляет код MBR и `MULTIOS/BOOT32.BIN`, сохраняя disk ID и таблицу разделов.
Без него старый install обновляет только kernel/EFI, а ранний CPU guard останется
прежним. Новый готовый образ уже содержит актуальный MBR.
