# MultiOS 0.36 — проверка защиты RW

`0.36-dev-ioguard`, неопубликованная разработка. Полный локальный software gate:
**PASS, 14 этапов**. Реальное оборудование и удалённый GitHub Actions не проверялись.

## Доказательство исправления

До изменения кода на образе FAT32 воспроизведён сценарий:

```text
HAL rejected op=0 with -1; ignored-error finish=0 (must fail)
```

Тест намеренно записывал изменённый сектор, передавал HAL неверный LBA,
игнорировал отказ и требовал завершить операцию как успешную. До патча commit
возвращал 0. После патча возвращается первая ошибка, исходный сектор восстановлен.
Полный вывод воспроизведения приложен отдельно; это ожидаемый провал старого кода,
а не ошибка текущего проверочного прогона.

## Новые проверки

На каждом из FAT32/exFAT/NTFS проверены шесть игнорируемых отказов:

1. disk_write за пределами устройства;
2. disk_write с NULL-буфером;
3. disk_read за пределами устройства;
4. disk_read с NULL-буфером;
5. прямой multi_storage_read за пределами устройства;
6. прямой multi_storage_read с NULL-буфером.

Для каждого варианта проверены запрет новых прикладных записей после отказа,
сохранение первого кода ошибки, отказ commit даже при ложном успехе модуля,
откат исходных байтов, размонтирование и последующее успешное монтирование.
Затем проверены переполнение 4096-секторного undo-бюджета, полное восстановление,
новая транзакция и обычная запись KEEP.TXT. Прогон выполнен обычной сборкой
и ASan/UBSan; файловые образы проверены внешними базовыми утилитами.

В модель undo добавлены неверный read-адрес, NULL при чтении, явная отмена,
нормализация ошибочного нуля/положительного статуса и сохранение первого отказа.
В block64 проверен запрет callback flush после ошибок read/write/flush, без
потери возможности диагностического чтения. Нормальные границы, 512–4096-байтные
секторы и адреса выше 32 бит продолжают проходить базовые тесты.

Повторены 644 выбранных комбинации отказов на настоящих файловых образах:
226 random I/O, 198 staged copy и 220 NTFS streams/hardlinks. Это выбранные
границы сырой записи × ошибка I/O/завершение процесса, не полный перебор всех
состояний накопителя. Повторение одного набора под санитайзером не удваивает
число уникальных сценариев. 13 440 цепочек относятся к ограниченной модели undo,
а не ко всем возможным состояниям каждой ФС.

Внешние проверки: fsck.fat, fsck.exfat, ntfsfix, чтение mtype/ntfscat там, где
это доступно. ntfsfix не заменяет Windows chkdsk и полный анализ NTFS.

## Загрузка

В QEMU Q35 + OVMF загрузились три образа 0.36. Проверены версия, отказ пяти
опасным именам, write/copy/resize/write-at, сравнение содержимого, выключение
и сохранённые байты. Использовались временные копии, не исходные образы поставки.
USB-диск и клавиатура предоставлены прошивкой через эмулированный xHCI: это не
проверка нативного xHCI MultiOS. UEFI сохраняет Boot Services.

BIOS этой версии собран, но не проверен загрузкой: доступная сборка QEMU не
содержит требуемого PC/IDE-профиля существующего BIOS-теста. Это не PASS для BIOS.

## Воспроизведение

```sh
python3 tools/check_filesystems.py
make -j4 FS_PROFILE=profiles/filesystems-ntfs3g.mk build/fs-read-probe
MULTIOS_BOOT_MODES=uefi python3 tests/fs_path_boot.py PATH_TO_IMAGES
```

Для загрузки нужны QEMU и OVMF; при необходимости задаются OVMF_CODE и OVMF_VARS.
В reports/ полного комплекта находятся results.json и логи. Внутренние пути
в них заменены нейтральными обозначениями. После окончательного усиления
проверок выполнен повторный полный прогон; отчёты относятся к нему.
