# Проверки USB — MultiOS 0.26-dev-usb12

Статус: development, UNPUBLISHED, не Release 1.0. Физическое оборудование не испытывалось.

## Интеграционные проверки

QEMU 9.2.0, TCG, CPU 486, RAM 64 MiB. Каждый сценарий использует отдельную расходную копию образа. Ввод: `bios_input=usb-only`, QMP send-key → эмулируемая USB-клавиатура. PS/2 и COM1 не используются для ввода. COM1 используется только для чтения вывода ядра. Подтверждён именно нативный путь ввода.

| Сценарий | Результат |
| --- | --- |
| PIIX3 UHCI, USB 1.x Boot Keyboard | PASS |
| PCI OHCI, USB 1.x Boot Keyboard | PASS |
| OHCI: мышь в первом порту, клавиатура во втором | PASS; мышь отвергается, её драйвера нет |
| EHCI, USB 2.0 high-speed Boot Keyboard | PASS |
| EHCI: мышь в первом порту, HS-клавиатура во втором | PASS; мышь не обслуживается |
| ICH9 EHCI → companion UHCI, USB 1.x клавиатура | PASS |
| ICH9 EHCI → companion OHCI, USB 1.x клавиатура | PASS |
| Компактное BIOS-ядро + OHCI, расходный exFAT-образ | PASS |

В расширенных сценариях проверены: `usb` с активным нативным драйвером и счётчиком reports; команда `echo`; Shift; Left/Delete в редакторе; `unlock YES`, `write`, `type`, `sync`, `lock` на расходном FAT32-образе; отключение и подключение новой клавиатуры; ожидание её готовности по USB-инвентарю ядра; `disconnects=1`; штатный `exit` (isa-debug-exit=33). Компактный сценарий использовал exFAT, не расширенный NTFS RW-профиль.

QMP-чтение диагностической памяти после переподключения — только наблюдение за тестируемым ядром, не ввод команд через альтернативный драйвер.

## Ошибки, обнаруженные во время разработки

- Добавление статических DMA-структур превысило low-memory предел компактной сборки. Для компактного профиля введён меньший резерв контроллеров, для расширенного — четыре каждого типа. Оба профиля снова собираются.
- В компактной сборке отсутствовал i386 helper `__udivdi3`, используемый существующим файловым кодом. Добавлен `build/div64.o` в kernel link.
- Переподключение EHCI не запускало enumeration в idle-режиме QEMU, когда FRINDEX переставал продвигаться после остановки periodic schedule. Добавлен основной trigger по root-port change; FRINDEX оставлен как дополнительный таймер.
- Начальный тест использовал фиксированную задержку перед вводом после переподключения. Он заменён ожиданием `keyboards=1` и обновлённого счётчика отключений. Ранний ввод до готовности устройства не считается поддержанным.
- Модель `usb-ehci` QEMU не поддерживает companion registration. Для теста EHCI→OHCI используется `ich9-usb-ehci1` с поддержкой companion-портов. Это ограничение тестового стенда, не результат теста драйвера.

Неудачные промежуточные прогоны не выдаются за принятые результаты. Комплект содержит результаты успешных повторных сценариев.

## Модульные тесты

- Общий USB-enumerator: 16 сценариев, ASan/UBSan, PASS. Неверные длины и descriptor type, неподходящий interface/endpoint, MPS/скорость, ошибка GET_DESCRIPTOR/SET_PROTOCOL, необязательный SET_IDLE, ошибка arm, неподдержанный interval.
- HID: 50 000 fuzz reports и детерминированные клавиши/modifiers/6KRO/очередь, PASS.
- Редактор: 100 000 событий модели, PASS.
- PS/2/input profiles: mock-I/O тест настоящего драйвера, в том числе запрет PS/2/COM1 reads в usb-only, PASS.
- OSK: 56 ячеек, 95 printable ASCII, NEXT/SELECT, optional PREVIOUS, hide/reopen, PASS.
- Hardware inventory: границы PCI/USB-инвентаря и сброс диагностики, PASS.

`make all` и `make bios-rw` прошли. Новый BIOS RW kernel собран freestanding i386; неопределённых символов нет. Компактный kernel остаётся ниже резерва стека. Linker предупреждает о едином RWX-сегменте существующей архитектуры; защита памяти этим патчем не добавлена.

## Что результаты не доказывают

Нет испытаний физических UHCI/OHCI/EHCI, firmware handoff на реальных платах, low-speed сигналов реальной клавиатуры, питания, suspend, кабелей, хабов или контроллеров всех производителей. Нет теста USB storage и нет нового USB-блочного драйвера. Файловые тесты здесь — базовые операции на расходных образах, не повторная полная сертификация FAT32/exFAT/NTFS и не тест потери питания. Нативная x64 UEFI-интеграция новых HCD не выполнена; EFI-ввод остаётся firmware-backed.

Подробные инструкции и ограничения: USB_0_26_RU.md.

## Финальные образы поставки

Все три MultiOS-0.26-fat32.img, MultiOS-0.26-exfat.img и MultiOS-0.26-ntfs.img прошли отдельную загрузку BIOS на QEMU, CPU 486, 64 MiB RAM: соответствующая ФС смонтирована RO, выполнены `ver`, `fs`, `usb`, штатный `exit` (код 33). Проверены длина/CRC32 raw BIOS-ядра и совпадение с kernel.bin поставки. Эти smoke-тесты использовали serial-ввод в профиле auto; доказательством нативного USB-ввода являются отдельные USB-only сценарии выше.

x64 EFI-бинарник оставлен без изменений из 0.25; новый нативный USB-путь им не объявляется.
