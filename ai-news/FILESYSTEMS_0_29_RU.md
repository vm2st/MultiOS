# MultiOS 0.29-dev-fs-safety / MultiPulti

Неопубликованная разработка, не стабильный Release 1.0. Запись FAT32, exFAT и NTFS остаётся экспериментальной; первое разрешение — только `unlock YES` на расходном носителе. Этот патч усиливает отказобезопасность, но не реализует всю семантику NTFS/Windows и не снимает ограничения USB.

## Изменения

1. **FatFs / FAT32 и exFAT:** первая ошибка HAL или чтения таблицы UpCase сохраняется до завершения текущего disposable view. После неё bridge не выполняет новые read/write/flush/UpCase обращения. Ошибка не подменяется последующей; `finish` не объявляет успешный remount при latched error. VFS передаёт отказ механизму sector undo. Прямой regression-test падал на 0.28 и проходит на исправлении.
2. **Общий VFS для всех ФС:** отрицательный результат unlock всегда сбрасывает writable; положительный не трактуется как успех. Успешный unlock дополнительно требует mounted, отсутствие poison, действующий writable block provider, прежние kind/base/sectors, прежний драйвер и подходящую private undo-привязку. Ошибочный ответ модульного драйвера сам по себе больше не разрешает запись. Regression-test воспроизводит неверное разрешение на старом коде.
3. **Новые тесты:** actual bridge callback failures; malformed module unlock contract; реальные read/flush failures во время unlock; заполнение томов реальными ненулевыми данными, ENOSPC и побайтовый откат всего образа вне изменяемого журнала, включая неизменяемые locator footer. Обычные и ASan/UBSan-сборки проверяются отдельно.
4. **Чистота исходников:** стандартный поиск QEMU вместо абсолютного пути рабочей среды в двух старых тестах; относительные вычисляемые пути в configured upstream Makefile. Добавлен `.gitignore`, включаемый в source ZIP. Контакты и лицензии сторонних авторов сохранены.

## Какие операции доступны

| Возможность | FAT32 | exFAT | NTFS-3G |
| --- | --- | --- | --- |
| Создание, чтение, replace/append | Да | Да | Да |
| Каталоги, rename/remove | Да | Да | Да |
| Random write и resize | Да | Да | Да |
| Staged copy с проверкой и resume | Да | Да | Да |
| Именованные DATA-потоки, hard links | Нет | Нет | Поддержанный набор |
| Файл 4 ГиБ и больше | Нет по формату | 64-bit API, в пределах HAL | 64-bit API, в пределах HAL |
| Произвольный Windows volume без ограничений | Не заявляется | Не заявляется | Не заявляется |

Это список доступных API, не обещание полной совместимости всех вариантов формата. Copy по умолчанию переносит DATA, не все ACL/reparse/метаданные; для поддержанных ADS используется `copyads`. NTFS sparse resize может успешно увеличить логическую длину почти без свободных кластеров: отсутствие места проверяется при физической материализации записи. FAT32/exFAT resize в текущем адаптере материализует добавляемые нули. Нельзя считать эти разные семантики ошибкой.

## Готовые образы

В `images/` три самостоятельных raw `.img`: `MultiOS-0.29-usb-fat32.img`, `-exfat.img`, `-ntfs.img`. Каждый содержит FAT32 ESP, DATA выбранной ФС, private undo-раздел и исходники. Выберите один. Это не ISO, не архив для копирования на флешку и не автоматический установщик на выбранный физический диск.

1. Сделайте резервную копию данных флешки; запись образа заменяет разметку и данные в его диапазоне.
2. Запишите `.img` побайтово, например Rufus в DD-режиме. Проверьте устройство назначения.
3. Для нативного BIOS-профиля нужны BIOS/CSM с EDD, подходящий UHCI/OHCI/EHCI и доступная RAM, для тестов 64 МиБ. Нет 8086/286 и универсального запуска bare board без BSP.
4. В консоли выполните `ver`, `modules`, `usb`, `fs`. В USB BIOS-профиле ожидается `block: pc-usb-bot`.
5. Для первой записи используйте только расходную копию:

```text
unlock YES
md DEMO
write DEMO/HELLO.TXT "Hello"
append DEMO/HELLO.TXT "MultiOS"
type DEMO/HELLO.TXT
copy DEMO/HELLO.TXT COPY.TXT
cmp DEMO/HELLO.TXT COPY.TXT
resize COPY.TXT 64
writeat COPY.TXT 0 "TEST"
sync
lock
exit
```

`write`/`append` добавляют LF. После ошибки записи не пытайтесь принудительно продолжать: сохраните целый образ, перезапустите и используйте штатное восстановление. Не стирайте служебный журнал, не перемещайте разделы и не используйте файловые repair-утилиты параллельно с работающей ОС.

## Ограничения сохранены

- Все изменения 0.28 USB сохранены, но нет xHCI, внешних хабов, split, UAS, multi-LUN, 4Kn и произвольных USB-классов. Один direct device на host; клавиатуре и системному диску нужны разные контроллеры или другой ввод.
- USB диск: BOT/SCSI LUN0, 512-байтовые секторы, READ CAPACITY(10). HAL ограничен 128 ГиБ; поставляемые образы гораздо меньше. Системный носитель не переназначается после извлечения.
- Private undo имеет конечный бюджет до 4096 изменяемых секторов на одну операцию. Большая операция может получить NOSPACE из-за бюджета даже при свободном месте на DATA. Для больших копий используйте staged copy; документация API сохранена в `FILESYSTEMS_0_19_RU.md` и последующих файловых руководствах.
- Это не полная замена NTFS $LogFile и не абсолютная защита от физической потери питания. Нестандартные, повреждённые, грязные и гибернированные тома не следует принудительно открывать RW.
- UEFI x64 бинарник оставлен прежним, новый патч в нём не пересобран. Исправления 0.29 включены в готовое расширенное BIOS i386-ядро и в новые сборки из исходников. UEFI использует старый firmware-путь, а не новый native USB; не считайте его обновлённым ядром 0.29.
- Не проверены реальное железо, физический power-cut и Windows chkdsk. Полный перечень принятых проверок — `TEST_FS_0_29_RU.md`.

## Настройка и сборка

На внешнем компьютере требуется Python3, для GUI также Tkinter. Пример ATA-профиля:

```sh
python3 tools/customize.py images/MultiOS-0.29-usb-fat32.img --settings tools/ATA.INI --output MultiOS-ATA.img
```

Редактор создаёт новый файл, синхронизирует профили и CRC. Ручная правка одного INI обычным архиватором не эквивалентна этой операции. Подробности ввода и OSK сохранены в `USB_STORAGE_0_28_RU.md`.

Для нового расширенного BIOS-ядра распакуйте FULL-SOURCES рядом с `images/` и `tools/`:

```sh
cd MultiOS
make bios-rw
python3 tools/build_bios_rw_image.py ../images/MultiOS-0.29-usb-fat32.img ../rebuilt-ata.img
python3 tools/customize.py ../rebuilt-ata.img --settings ../tools/USB.INI --output ../rebuilt-usb.img
```

Нужны GCC/binutils с i386 code generation, make, Python3 и mtools. Installer обновляет согласованные MBR/loader/raw kernel/ESP payload и source ZIP; заменить только `KERNEL32.BIN` недостаточно. `bios-bundle/` содержит готовые согласованные файлы, параметр `--bundle` позволяет использовать их. Linux нужен для разработки, не для работы BIOS-ядра.

Host-тесты полного NTFS-3G/FatFs-профиля собираются явно:

```sh
make FS_PROFILE=profiles/filesystems-ntfs3g.mk build/multios-host
make test-fatfs-bridge test-unlock-contract
```

Обычная `make all` — другой компактный профиль. Он не эквивалентен расширенному NTFS RW-ядру. Сторонние NTFS-3G/FatFs и их лицензии остаются частью исходников; объединённое ядро с NTFS-3G распространяется по GPL-2.0-or-later.
