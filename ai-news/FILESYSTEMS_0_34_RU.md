# MultiOS 0.34 — защита путей при записи

Неопубликованная разработка `0.34-dev-pathguard`. Не стабильный Release 1.0.

## Исправление

В профиле FatFs запись по пути `KEEP.TXT.` могла изменить существующий
`KEEP.TXT`: движок отбрасывал завершающую точку. Аналогичные неоднозначности
возникали с завершающими пробелами и ненормализованными компонентами пути.

Общий слой VFS теперь проверяет каждый компонент пути **до начала транзакции**.
Это относится к созданию, замене, добавлению данных, созданию каталога,
копированию, удалению, переименованию, произвольной записи, изменению размера,
изменению именованных потоков и созданию жёстких ссылок.

- Путь должен быть абсолютным, непустым и укладываться в `PATHMAX`.
- Пустые компоненты, `.` и `..` в запросе VFS не допускаются.
- Завершающие точки/пробелы, запрещённые символы и повреждённый UTF-8 отклоняются.
- При переименовании отдельно проверяется новое имя.
- При копировании и создании ссылки проверяется также путь источника.
- Некорректный запрос не записывает секторы, не начинает undo-транзакцию,
  не размонтирует исправный том и не инвалидирует открытое файловое представление.

Пробелы внутри имени, допустимый Unicode, вложенные каталоги и штатный поиск
имени без учёта регистра сохранены. Нормализация пользовательских команд
остаётся в оболочке; драйверы получают уже проверенный путь. Это защитный
контракт записи MultiOS, а не обещание поддержки всех допустимых имён Windows.

## Сборка и проверка

```sh
make -j4 FS_PROFILE=profiles/filesystems-ntfs3g.mk build/fs-path-probe
python3 tests/path_safety.py
make -j4 FS_PROFILE=profiles/filesystems-ntfs3g.mk build/fs-path-probe-sanitize
MULTIOS_PATH_PROBE="$PWD/build/fs-path-probe-sanitize" python3 tests/path_safety.py
```

Нужны Python 3, компилятор C, `dosfstools`, `exfatprogs`, `mtools`,
`ntfsprogs` и библиотеки ASan/UBSan для санитарной сборки. Тесты создают
одноразовые файлы-образы в `build/`; доступ к физическим дискам не требуется.

Для загрузочных компонентов:

```sh
make bios-rw
make -j4 FS_PROFILE=profiles/filesystems-ntfs3g.mk uefi
```

Используется существующий ABI файловых модулей; формат томов и undo-журнала
не меняется. После изменения C-кода требуется пересобрать BIOS-ядро и EFI-файл.
Простое редактирование конфигурации не обновляет исполняемый код.

## Статус

Повторены проверки FAT32, exFAT и NTFS на обычную запись, resize, обнуление
расширенной области, поэтапное копирование, отмену/возобновление и выбранные
отказы записи. Отчёт: [TEST_FS_0_34_RU.md](TEST_FS_0_34_RU.md).

Конечный undo-бюджет, запрет записи на неподготовленные/опасные тома и прочие
ограничения предыдущих профилей сохраняются. Полная Windows-совместимость NTFS
(включая все политики ACL, EFS, reparse и `$LogFile`) не заявляется. Проверки
на образах не заменяют проверку реальных контроллеров и отключения питания.
